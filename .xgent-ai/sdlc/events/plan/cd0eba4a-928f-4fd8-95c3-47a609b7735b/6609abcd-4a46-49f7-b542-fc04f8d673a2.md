# 九包 0.2.1 补丁版已公开发布

- 事实与证据：R1 的 F-3 修复只改 `rustify-docs-cli`，但 CLI 版本号改动必然改根 `Cargo.lock`，发行脚本 `ensure_libraries_unchanged` 实测拒绝按旧 R 冻结（`freeze refused: ... Cargo.lock`），crates.io 的 0.2.0 又不可覆盖，因此九包一起进 0.2.1。库候选 R `b32844a4`、CLI C `8fd7fd63`、文档 `0efbea59`；九包上传后公开 API 校验九个 checksum 与 receipt 逐一 MATCH；staging `verify`、`verify --public-docs`、`verify --public` 均 passed；远端 [run 40086656527](https://github.com/rockie/rustify-ui/actions/runs/40086656527) 的 macOS 与 Ubuntu 两个 job 均 success；八个库 docs.rs 0.2.1 文档页 200；标签 `rustify-libs-v0.2.1`、`rustify-docs-cli-v0.2.1` 已推送并读回。详见 [M6 记录](../../../../docs/plan/CRATES-IO-P1.records/M6.md#021-补丁发布2026-10-24-1926-0800)。
- 校准依据：计划仍写 6/6 与「修复版尚未发布」，本轮把快照改为 0.2.1 已发布；库包源码与行为相对 0.2.0 未变，只有版本、内部钉、锁与归档身份变化，所以不把 0.2.1 记作新功能交付。
- 未完项与限制：未重跑 0.2.0 的 333 项浏览器矩阵与作者迁移全量；首次上传遇 LibreSSL SSL 连接错误，核实 crates.io 无 0.2.1 后用同一 receipt 重试成功。运行支持边界不变（本地 macOS Chrome，Windows 与完整 Linux 运行未验证）。
- 下一步及解除条件：本期收口，无待办；后续变更按计划 §5.4 换版本、重冻 R/C 后重新走发行门。
