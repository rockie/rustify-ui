## 3. 差距清单（按严重度、再按可挽回分排序）

### 新-1 · [P1] 深色局部边界内打开的对话框：表面随边界变深，主按钮 Confirm 仍取根主题浅色 primary（回归）
- **单元与截图**
  - U5，`U5-local-opposite-dialog-1440-light`。对话框 x 209–1230、y 17–176，表面 #1D2939。Confirm 位于 x 233–311、y 118–152，填充 #1570EF，文字 #FFFFFF。
  - 对照一（同一边界内的控件）：`U5-local-opposite-1440-light` 中 Actions 文字为 #53B1FD，边界底色为 #101828。
  - 对照二（深色主题的 solid 按钮）：`U5-dom-1440-dark` 中 Create profile 填充为 #53B1FD。
  - 对照三（R3 同帧）：Confirm 为 #53B1FD 底、#0C111D 字。
  - 浅色根下的 `U5-dialog-1440-light` 中 Confirm 为 #1570EF，这是正确的。
- **维度**：视觉、交互与状态
- **现状 → 期望**：同一个浮层里，表面和文字跟随了深色边界，主按钮却取根（浅色）主题。期望整个浮层（含其中的 Button）按创建处的有效主题渲染，即深色 primary #53B1FD 及其前景色。
  - 依据：P3「局部浮层随创建处的有效主题更新；修改任一区域不改变其边界外的主题」。对话框正文本身也写着「This layer follows the theme where it was opened.」，按钮与这句话矛盾。另有 B6「未选 color 的 solid Button 消费有效 primary/foreground」作为旁证。
  - 后果：作者检查深色嵌套浮层时，会把 #1570EF 误当成自己深色主题的主按钮色。
- **修法**
  1. 让 Dialog 的 portal 容器带上创建处 ThemeBoundary 的完整作用域。可以把 portal 目标放在边界的主题元素之内，也可以在 portal 根上复制该边界的 appearance class 或 data 属性，以及全部主题 CSS 变量。不能只同步表面所需的 popover / foreground 变量，Button solid 用到的 primary 及其前景、第 9/10 阶、contrast 变量都要带上。
  2. Button solid 的填充色与文字色必须从最近的作用域取 CSS 变量，不要在挂载时把颜色固化成内联值，也不要从根 scope 读取。
  3. R3 被测版本 `d5775d8` 上这个按钮是正确的。把它和 R4 `5d122d6` 之间对 Dialog、Button、ThemeBoundary、portal 的改动逐一比对，按钮尺寸的变化（新-2）大概率是同一处改动带出的。
  4. 补一条浏览器回归：在「Opposite to root」边界内打开对话框，断言 Confirm 的 computed `background-color` 等于同一边界内 solid 按钮的值（Rustify Light 深色为 #53B1FD）；切回「Inherit root」再开一次，断言为 #1570EF。
- **可挽回分**：0.4（视觉 0.2 + 交互与状态 0.2）

### UI-76 · [P3] DOM 与 GPU 两框首行纵向差 9px（横向已对齐，纵向回归）
- **单元与截图**：U5，`U5-gpu-compare-1440-light`。两框上边框都在 y=335。DOM「Local demonstration」大写字母顶部在 y=357，GPU「GPU · Cards」在 y=366，首行基线相应也差约 9px。390 宽度下两框上下堆叠，不受影响。
- **维度**：布局
- **现状 → 期望**：R3 时纵向对齐、横向差 8px；本轮把 GPU 场景根的内边距加大后，横向对齐了，纵向错开 9px。期望两个渲染器框的首行在两个方向上都对齐，便于逐项对照（P5 并排比较；沿用 R3 尺度）。
- **修法**：给 GPU 场景根与 DOM 框使用同一个 padding token，上边距也要统一。按字形位置推算，DOM 框首行之上的内边距比 GPU 少约 9px。若两框首行字号不同（GPU 标题比 DOM 说明行大），就以首行基线对齐为准，调整 GPU 场景根的 `padding-top`，不要动左右边距。
- **可挽回分**：0.05

### 新-2 · [P3] 预览对话框 Confirm 为 79×35，与同一预览里 32px 高的 solid 按钮不一致（R3 为 77×33）
- **单元与截图**
  - U5，`U5-dialog-1440-light` 与 `U5-local-opposite-dialog-1440-light`：Confirm 位于 x 233–311、y 118–152（79×35）。R3 为 x 233–309、y 118–150（77×33）。
  - `U5-dialog-390-light`：x 41–119、y 141–175（79×35）；R3 为 77×33。
  - 两轮的「Confirm」文字墨迹都是 51×11，即本轮四周各多出 1px。
  - 对照：`U5-dom-1440-light` 中 Create profile 为 115×32（x 394–508、y 645–676），Create · 0 为 89×32。
- **维度**：细节
- **现状 → 期望**：期望预览里的同级主按钮采用同一尺寸档。依据是 P1「预览使用真实组件、变体、尺寸」。如果这个按钮是 P1 Button，还应符合 size 2 参考高 32px（U5 比较口径注明 P1 新组件按其规范比较）。
- **修法**：对话框的操作按钮改用与 Create profile 相同的 Button（size 2），去掉多出的那 1px（新增的边框或 padding），并确认 `box-sizing` 一致。与新-1 一起排查：若是 portal 内的按钮没有取到边界作用域的尺度与间距变量，修好新-1 后应同时恢复。修完量一下，Confirm 应为 32px 高。
- **可挽回分**：0.05

### 新-3 · [P3] 卡片选中框内圈在滚动区边缘画出闭合底边，看上去像卡片在 y=720 处结束
- **单元与截图**
  - U5，`U5-inspector-card-1440-light`。外圈 2px #1570EF 在 x 365–366 / 870–871，顶边在 y 361–362，向下延伸到滚动区边缘、不闭合。内圈 2px 在 x 369–370 / 866–867，顶边在 y 365–366，在 y 719–720 画出一条横跨 x 369–867 的底边，紧贴面板上边框（y=721）。
  - 这张卡实际延伸到 y≈787：`U5-dom-1440-light` 中卡片为 y 388–810，本帧预览整体上移了 23px。
- **维度**：细节
- **现状 → 期望**：内外两圈一圈闭合、一圈开口，而且闭合处不是部件的真实边界。期望选中矩形如实框出实际部件（P2「从实际部件定位……选中矩形为固定蓝色 outline」），被滚动区截断的一侧保持开口。
- **修法**：两圈都用部件完整的 `getBoundingClientRect()` 绘制，不与滚动视口求交；覆盖层放在预览滚动容器内并 `overflow: clip`，由容器自然裁切。如果坚持把矩形钳制到视口内，就在部件超出可视区的那一侧去掉该侧描边（例如部件底边低于视口时 `border-bottom: 0`），内外两圈同样处理。
- **可挽回分**：0.05

**可挽回分合计**：0.4 + 0.05 + 0.05 + 0.05 = 0.55 = 10 − 9.45。

## 4. 建议（不扣分）

沿用 R3 的建议，本轮仍成立：
1. 简单对话框限宽 28–32rem 并垂直居中。本轮仍贴顶通栏：x 209–1230、y 17–176。
2. 菜单与触发器之间留 4px 并加层级阴影。本轮菜单仍紧贴 Actions 下沿，`U5-menu` 与 `U5-local-opposite-menu` 中触发器底约 y≈538 / 543，菜单顶边约 y≈539 / 544。局部边界的标题可以升一级，外观选择器可以限宽（目前通栏 x 411–1348）。
3. GPU 色样标签不在连字符处断开（`U5-gpu-compare` 中「card- / foreground」「popover- / foreground」「primary- / foreground」）；Host control 加一行说明。
4. 深色局部对话框的遮罩改取根主题或中性深色。本轮仍是浅色遮罩：`U5-local-opposite-dialog` 中编辑区取样 #FDFDFE，预览底取样 #F9FAFB，几乎没有压暗。
5. 拾取面板补充色阶信息（属 F19）；提供折叠入口。
6. 390 下 Preview 页的粘性页头收成一行（属 U1 范围）。

本轮新增：

7. **面板高度随内容变化**：有 token 按钮时 161px，未标注时 121px。悬停在不同部件之间移动时，预览滚动区的可视高度会跳 40px。建议给面板设 `min-height`（按有 token 按钮时的高度），让滚动区高度稳定。
8. **滚动区与面板之间无间隙**：内容在 y=720 被齐刷刷切断，面板边框在 y=721，「Sample actions: 0」被切掉一半。建议留 8px 间隙，或在滚动区底部加一道淡出阴影，提示下方还能滚动。
9. **UI-188 修法的副作用：同一行按钮字重不一**。`U5-dom-1440-light` 中 DOM / GPU / DOM + GPU / Inspect / Focus preview 为半粗，而 Cards / Responsive 为常规；`U5-preview-390-light` 中「Inspect」「Focus preview」半粗、紧邻的「Back to edit」却是常规。建议未按下的标签统一用常规字重，按下时加粗，并用隐藏的粗体伪元素预留宽度；或者整行同一字重。U5 的规范列表（P1–P5、G1）没有对应条款，所以只作建议。
10. 面板标题「Inspect preview tokens」与正文同字号同字重。面板里的色值「#1570ef」「#ffffff」用的是比例字体，而编辑器里的有效值用等宽字。可以按 G3（label 13px/600、颜色值等宽 12px）统一；G3 不在 U5 的规范列表内，只作建议。

## 6. 总评

- **最低分单元**：本次只评 U5，得分 9.45，与 R3 持平。R3 留下的四条交互和布局问题都已关闭：浮动面板遮挡被拾取部件、标签盖住相邻内容与断词、预览模式与主题名连读、按下态横移。
- **主要失分**：新出现的 P1 回归（新-1）。深色局部边界内的对话框里，主按钮取了根主题的浅色 primary，P3 的核心承诺（浮层随创建处主题）只做到一半，而 R3 时这里是正确的。其余是三处 P3：两框首行纵向差 9px、Confirm 尺寸偏离 32px、选中框在裁切边闭合。
- **是否需要结构性改动**：
  - 布局不需要推倒。拾取面板已按上轮建议改成预览列底部的网格行，结构正确。
  - 新-1 需要在主题作用域层面修，不是改一处颜色：对话框（以及所有 portal 浮层）的作用域要覆盖其内部全部组件所用的主题变量，并补一条「相反外观边界内浮层 computed 颜色」的浏览器回归，防止再次回退。
