## 未关闭差距

### UI-217 · U1 · 已配置品牌色后的选择列表缺少可见键盘活动项

- **维度／严重度／可挽回分：交互与状态／P1／0.5 分。**
- **截图与位置：**
  - `U1-matrix-keyboard-03-768-light.png`：左侧 Brand color 展开列表。
  - `U1-matrix-keyboard-03-390-light.png`：编辑区 Brand color 展开列表。
  - `U1-matrix2-keyboard-03-1440-dark.png`：左侧 Brand color 展开列表。
- **现状：**三张图的触发器均显示 `Pink`，可见列表均从 `Custom` 排到 `Orange`，可见选项没有活动项蓝底、蓝字或其他键盘焦点标识；触发器原有焦点环也已消失。操作记录将这组流程标为真实键盘聚焦以及 `Enter/ArrowDown/Escape`。键盘用户在这个已拍状态无法从画面辨认当前正在移动到哪个选项。
- **期望与依据：**目标 **G4「新增控件键盘可用、焦点可见」**要求键盘活动位置能够被看见。对照本轮默认状态的 `U1-keyboard-03-1440-light.png`，其中 `Custom` 有选中勾，`Gray` 有清楚的蓝色活动行；已配置状态也应提供同等可辨认反馈。
- **具体修法：**修改 Studio 基础配置的品牌色选择器及其列表弹层：展开时定位当前值；每次方向键改变活动项后，将该项滚入列表可视区，例如对活动项执行 `scrollIntoView({ block: "nearest" })`；活动项保留蓝色背景／文字反馈，当前值保留独立选中标识。修后从 Pink 这类位于首屏列表之外的值开始，补拍展开、连续方向键移动、确认选择和 Escape 返回焦点。
- **判断边界：**截图不能确定活动项是落在列表可视区外，还是活动样式未呈现；这两种实现原因需要修复方定位。本项只扣已经可见的反馈缺失，不推断键盘确认必然失败。

可挽回分合计 **0.5**，等于 **10 − 9.5**。

映射：U1-b 与 U1-c 的「新-1」均为 Pink 起点展开菜单后的活动项不可见；同一单元、同一三张图、同一交互偏差，合并为 UI-217。采用较低整组评分 U1-c 的可挽回 0.5；U1-b 的原始 0.4 保留在独立原文。

### UI-216 · Code ghost 的 color／high-contrast 文字仍带强调色

- **单元与截图位置**：U7；`U7-type-code-matrix-1280-light.png` 的 ghost 行前两列，及 `U7-type-code-matrix-390-light.png` 中 ghost 组的 `color=indigo`、`indigo · high_contrast`。
- **维度**：视觉。
- **严重度**：P2 一般。
- **现状 → 期望**：
  - 当前 ghost 的 color 样例呈明显靛蓝色，high-contrast 样例呈深靛蓝色，与同组 gray 的中性文字形成色相区别。
  - 目标 `radix-sink-code.png` 表格的 ghost 行中，color 与 high-contrast 两列均采用接近正文的中性前景；强调色处理保留在上方 solid／soft／outline 变体中。
  - 期望依据为目标图 **Code 表格 ghost 行前两列**、U7 比较口径中的 **Code 外观**，以及 L1 的正确语义外观要求。这里比较的是 ghost 的前景处理，不对已接受的低对比情况另行扣分。
- **具体修法**：
  - 调整 **Code 的 ghost 变体前景分支**：使当前强调色 ghost 样例使用有效主题的中性 foreground，high-contrast 样例也与参考中的中性高对比前景对应。
  - 保留 ghost 的无填充、无描边外观；单独复核显式 gray 分支，避免把其他三种变体一起改色。
  - 修后并排核对 1280、390 的四列矩阵，并确认下方 ghost 字级阶梯仍使用正文前景。
- **证据定位**：目标图 ghost 行约在本地图像 `y=309`，当前 1280 分段图对应行约在 `y=294`；当前前两列分别位于约 `x=112`、`x=388`。
- **可挽回分：0.3**。

映射：U7-a「新-2」→ UI-216；U7-b 没有另列此项，但按差距并集保留 U7-a 的发现和 9.7 整组分。R5 的 Kbd「新-1」是 UI-214，本轮已解决，不复用编号。
