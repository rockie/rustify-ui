## 当前交付

定位前置保留：Side 四边、FloatingPosition/CollisionPadding/Sticky/PositionUpdate/ViewportAlign 与数值错误类型；纯几何覆盖 RTL、offset、碰撞翻侧/shift、padding、sticky、箭头输出、detached 与可用尺寸。Layer 的可选 position 使用新坐标；旧 Region/fit 仍走旧坐标路径。同 scope boundary ID 与数值整体验证后缓存最后有效配置，错误投影到 data-rustify-issue，CSSOM 写可用尺寸。前批非法 boundary 整体缓存回归已修复。

`overlay/hierarchy.rs` 现在拥有唯一父关系、登记序列、活动 modal 与显示顺序；通知迁移根跟随 top modal，包含新 modal 的祖先分支保持原链，避免自环。父层移除先迁出独立通知子树，再按后代到祖先顺序撤销普通分支。真实栈已使用该模型，迁移不重分配 LayerId。

Layer 有独立 Owner/父引用、active、panel 与显式回焦 trigger_id；active=false 不注册，SSR 关闭初态不报浮层初态错误。panel 就绪后才注册/度量，实际 outside 与焦点根使用 panel，旧调用仍用外框。每层有零尺寸、无 transform 的 children/notifications host，后代 Portal 挂入父面板。scope 捕获阶段统一约束 top modal 的 Tab/focusin；inert 只声明自己新增的属性，避开包含当前 modal 的祖先分支。直接 modal Layer 已省略 aria-modal。主题、lang、dir 继承创建位置。

新增 FocusOutside、focus/interact hooks，共享专属→interact 的同一个取消状态；pointerdown 与同次 focusin 合并。非模态允许外部原生操作，模态焦点约束只在本 scope 内。active 关闭与恢复的 auto_focus 各一次；层级清理 callbacks 在锁外，资源沿现有 listener/resize/abort 链释放。

ToastRegion 改用栈持有的 NotificationPortal：同一个通知 DOM 和 Owner 移入当前 modal 的 notifications host，动态父引用供新浮层读取；已有迁移根及其后代保持身份、草稿与顺序。没有引入新的计时/队列实现。通知打开 modal 时，modal Portal 独立于 Viewport DOM，保护祖先链，Viewport 可以进入新 modal 而不自包含。迁移时只恢复仍存活通知子树内的有效原焦点；已有外部有效焦点不被缓存覆盖。

生命周期现在检查实际 panel 的连接状态和显式 Trigger 的存在/禁用/可见状态；失效后隐藏、移除注册和实际 resize 观察、请求关闭一次，业务 open 不被写入。活动调用共享 scope 的树/size/scroll/resize 观察，失去最后一条注册时仍能发现恢复；active=false/Owner 清理后释放该调用的观察份额。树观察仅订阅 childList 与 disabled/hidden/id/aria-disabled，不监听自身坐标 style 写入。NativeTextEdit 的 begin/end 编辑也保持这条 movement 观察，不丢原滚动重定位。普通父引用未注册时子层等待，不误发关闭。

默认回焦通过已有 runtime.defer 等当前原生事件结束，再检查当下焦点和候选是否仍有效；外部按钮保留焦点，不可聚焦 surface 关闭后回 Trigger。scope 结束的 Weak 引用阻止旧恢复任务继续操作。关闭 auto_focus hook 仍可取消默认。radio Tab 域现在按浏览器 input.form 与 name 分组，包含显式 form 属性；只增加 web-sys 的 HtmlFormElement feature，没有新依赖版本。

`Anchor::Viewport { align }` 的 host/browser 已同步，Center/Start 采用 scope 可见交集及 1rem 内距；纯函数返回可用宽高及坐标。Layer 用同一 bounds 向外框投影 `--rustify-layer-scope-{x,y,width,height}` 和 available 尺寸 CSSOM 变量，退出 Viewport anchor 时清除自有投影。fixture 的独立两 scope 面板/遮罩使用这些值；Dialog/AlertDialog 的结构 CSS 与 Themes Content 已消费这些可用尺寸，Overlay 使用同一 scope 矩形。无可见区域时挂起注册并只请求一次，滚回/恢复显示后重入；旧 Centred/Element/Region 的坐标语义保留。

## 对话部件与迁移

`primitives/floating.rs` 提供受控 Root、Portal 的唯一 Layer、Overlay 与 Content、原生 typed Trigger/Close/Cancel/Action 和名称登记。Dialog/AlertDialog 命名空间共享该行为；AlertDialog 始终 scope-local modal。实际 Content 使用 dialog/alertdialog 角色并省略 aria-modal；Title/Description 关联随实际节点及非空文本变化，缺失/重复部件诊断，不引用失效名称。无 Trigger 的程序打开合法；延迟 Trigger 与重复部件修复按当前唯一存活部件恢复。

force_mount 仅保留关闭 DOM 与草稿，关闭仍 hidden/inert。普通对话默认聚焦首项，无项回 Content；AlertDialog 默认 Cancel，缺 Cancel 回 Content，不默认落到危险 Action。原生目标先执行，取消后不发组件请求；Action 自有 Cancelable 回调再决定是否请求关闭，其他关闭路径不发确认。应用拒绝关闭时内容保持可操作。非 modal 的 Overlay 不挂载，遵循正式 Dialog 参考的 modal 分支。

Themes `dialog::Content`/`alert_dialog::Content` 有四档 DialogSize、响应式 Layout 与 margin、Start/Center；Title/Description 有语义 level/既有 Margin，样式消费已解析空间、字体、半径、surface 和 shadow。旧 `Dialog` 便捷视图以同源 parts 组装标题/关闭栏，保留既有 class/test_id/data-name 和创建处主题；close_on_backdrop=false 映射到取消 outside 默认。Studio 三处顶部编辑/preview 调用改用 Start，旧 width/max-width/max-height 消费可用 scope 变量，避免 viewport 宽度越过局部 scope。旧能力描述及 aria-modal 测试已同步，完整新增 Catalog 条目仍在 M7/V-14 收口。

对话真实挂载暴露了此前 core 探针未覆盖的生命周期问题：打开 hook 早于 Content hidden/inert 更新，改为 runtime.defer 后核对当前 LayerId；同步焦点恢复重入 FnMut focusin，改用同一 listener/abort 链的 Fn 监听；正常 Portal 卸载时 Content hook Owner 先释放，增加 `overlay::on_layer_content_cleanup()` 的最小跨 crate 接线。Root 保留 align 值，避免重开读取旧 Content Signal。关闭回调内重开后跳过旧 session 默认回焦。重复 Content 删除后原 panel ref 曾指向已卸载节点，现由各 Content 的局部 NodeRef 将唯一存活 panel/hooks/align 投回 Root。两消费者验证了修复结果。

补齐 Dialog 引用的正式 `base-dialog.css`，以同一 vendor/revision/许可闭包登记到 sources.lock.json；正常构建不依赖 ref/。
