旧差距逐条复核：

1. **旧「新-1」｜仍存在｜视觉｜P2｜可挽回 0.5 分**

   **位置：**`U3-ColorField-invalid-1440-light.png`，中部颜色输入行，显示 `#336699` 的区域。

   **现状 → 目标：**实际字段用红框呈现 invalid，附近没有文字或其它非颜色状态提示。上方 `State: Invalid` 可说明演示配置，但字段本体仍只靠颜色表达错误。冻结 G-2 要求控件具有帮助和状态，且不只用颜色反馈；U3-1 要求 invalid 可区别。

   **具体修法：**在字段旁增加简短、明确的错误状态文字并关联编辑元素；若这是强制 invalid 演示，应直接说明其演示性质，不必编造当前颜色值为何无效。保留现有边框反馈。

2. **旧「新-2」｜仍存在｜交互状态｜P2｜可挽回 0.5 分**

   **位置：**`U3-TextField-s2-surface-1440-light.png` 中部 `Example` 输入行；同组 TextArea、NumberField、ColorField 试验输入区域，以及补采 undo/a5 中的同一试验字段。

   **现状 → 目标：**输入行没有自身的可见标签与字段专属帮助。`Component` 属于组件选择器；通用说明解释请求机制，未替代具体字段的标签或数字／颜色格式帮助。冻结 U3-1 要求字段标签、名称、帮助指向编辑元素，G-2 要求控件具有标签与帮助。

   **具体修法：**补充简短可见标签，并为数字／颜色字段提供相关格式或操作说明，关联实际编辑元素。现有区域结构可以保留。

   本项仅确认可见信息缺失，**不推断 accessible name 或辅助技术关联也缺失**，未据此判定 AA 失败。
