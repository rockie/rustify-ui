## 交付

- 根 `ThemeScope` 按作者 appearance 选择模式，显式 `preview_mode` 可覆盖根；Studio 两个预览传入各自模式，不修改作者文档。`ResolvedTheme::in_mode` 使用同一完整来源与原解析环境。
- `ThemeBoundary` 接收两模式 `ThemeBoundaryPatch`，保留 config Keep/Set、两模式 token、来源与未缩放作者表；空 patch 复用父快照，清除上次完整 CSS 属性与模式标记；非法 patch 回退父快照并诊断。旧模式无关 patch 通过 `From<ThemeValuePatch>` 显式适配。
- 局部浮层仍订阅创建处有效 signal，不另解析文档；相反模式、父配置更新与解除局部选择同步投影。静态绑定保留同一双模式来源。
- 根属性/优先级与模式标记由包内 `web/theme.js` 捕获，普通 cleanup 与 runtime abort 调用相同纯 JS release，不回调已失败 Wasm；其余实例/作用域不受影响。
- dark utilities 使用根/边界/浮层模式标记和继承 mode 属性的 style query，局部强制浅色可以阻断外层深色，内层仍可再次深色；宿主 `.dark` 不决定 SDK 模式。同步包内皮肤与文档。

## 实现校正与后续边界

最初使用嵌套 `@scope` 定义 dark variant，最小CLI实验表明固定Tailwind4.1.13未保留utility选择器，压缩输出为空块；真实浏览器用例先在深色4px边框上失败。改用继承模式/style query后本组通过，无工具链升级。角色和颜色仍由同一快照决定，未引入全局观察器。

M3退出 V3 与受影响GPU共享路径已通过；当前3/7。根 JS abort 已接入既有生命周期，完整实例fatal/重启/持久化恢复仍由 M7 取证，不在本批冒称通过。新基础组件/SSR响应式、Studio配置与存储安全、完整导出/消费者、终验与后测均尚未完成。继续 M4，累计提交时回填 M3/M4 的同一个实现 SHA。
