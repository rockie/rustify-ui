## 本批发现与修复

1. **DOM Slider 高亮与底轨错位（用户反馈）**：实际 Chrome 的 1280px、根字号 16px 截图，填充中心 13.5px、底轨中心 8.5px，差 5px，像素断言先红。原因是 WebKit thumb 顶齐 runnable track，而填充来自 thumb 的裁剪阴影。仅在该 thumb 加 `margin-top: calc(0px - var(--clip-top))`，复用实际手柄/轨道高度差，不写固定像素；已重新生成 SDK CSS。`7b615983d6fbd6b4` 实际构建中 `theme-slider.spec.ts` 两项通过，1280/390 × rem 16/20 四组中心误差 0/0/0.5/0.5px，原生键盘和 pointer drag 通过；四图均已目视审核。[修复前后像素和 PNG](../../validation/dom-components-p1/acceptance/slider/)。CSS check 62,536B / 4,435 candidates，fmt 通过。
2. **主题投影重复写入**：完整 source 参与解析相等性是嵌套双模式语义所需，但父主题 primary 改动被 neutral toolbar 完全覆盖时，仍写 203 个未变 CSS 属性。真实 CSSOM 红测已确认 CSS 字节不变而 `setProperty` 调用 203 次；Boundary cache 后已绿为 0 次。该构建的配置/DOM/Slider/投影 15/15、完整 journey/GPU/回滚 19/19、catalog 嵌套模式/失效/清理 3/3 全通过，日志 `/tmp/rustify-p1-m7-ui-fix-{browser,journeys,boundaries}.log`。性能中 projection p50 7.3→6.7ms，根仍重写 203 项；新增根 CSSOM 断言先红（`projection-root-red.log`）。因此将差异投影抽为根与 Boundary 共用的私有 helper，仅写值变化项，并从 previous map 剩余项移除消失的属性；mode+值缓存独立于完整 source context。根单 primary 编辑现已绿测为只写 `--primary`；最终重建、回归及性能见下节。浮层保留既有投影路径。
3. **磁盘/构建缓存**：本机 ENOSPC，mbx 低空间自动 GC 回收了 managed targets，根 target 曾成为悬空 symlink；源码和仓内证据未丢。只将确认悬空的根 target 恢复为普通目录，后续显式 `CARGO_TARGET_DIR=<repo>/target MBX_TARGET_VIEWS=0`，不改全局配置。所需 CLI/Studio/Fusion 已实际重建；未把中断命令算通过。
