## 交付

- `landing.rs`：`Load`、`ScriptSrc`、`Script`、`Sources`、`Profile`；`valid_name`、`valid_carry`、`parse_source`、`parse_script_src`、`policy`、`meta_policy`、`allows`。
- `config.rs`：`RawLanding`/`RawProfile`/`RawScript`/`RawSources`（均 `deny_unknown_fields`），`parse_landing` 写入 `Config.landing`；`nav_links` 从 `parse_nav` 抽出供页脚复用。
- `frontmatter.rs`：`Layout::Landing`、`Layout::has_hero`、`Front.landing`、`indexed`/`searchable`/`discoverable`。
- `content.rs`：`landing-without-layout`、`landing-profile`（定位到 frontmatter 中 `landing:` 的值）；`landing-script-missing`（沿用 `Refusal::issue`，私有文件报 `private-file`）；`landing-profile-unused`；`Analysis.landing_footers`；`has_hero` 替换 H1 并入、description 省略、侧栏三处。

## 实现中的决定

- 配置表的 span 是表头 `[landing.profiles.<名>]`，`landing-profile-name` 与 `landing-profile-unused` 都定位在这里。
- 本地脚本必须是 `.js` 文件（`parse_script_src`），否则报 `landing-script`；计划只说“合法相对路径”，`.js` 限制是为了浏览器按脚本执行。
- 通配来源的后缀至少两段（拒绝 `https://*.com`），属于 D6“最小放开”的就地细化。
- 所有配置（包括未被引用的）的本地脚本与页脚链接都做存在性校验并发布，同 `theme.logo`、`nav.top`。
- `generation.rs:812,1139,1172,1082`、`search.rs:113`、`ai.rs:36,125` 的替换按 T-1 留在 M2。
