## 偏差与修复

1. **iframe 透传（§5.6 第 4 步，产品缺陷）**。docs-root/subpath/meta 的 `the frame is embedded with the carried parameters` 失败：trace 显示嵌入在 `site.js` 执行前已按原地址开始加载，之后再没有带参数的导航。用一个最小页面（懒加载 iframe，`defer` 脚本延迟 0–150 ms 改写 `src`）复现：Chromium 在改写落在懒加载刚触发后的 2–4 ms 窗口时丢掉这次改动，嵌入停在原地址；6 ms 之后改写会重新导航，但 `history.length` 从 2 变 3（返回键先退回嵌入）。WebKit 对懒加载 iframe 加载两次，对非懒加载的同样多一条历史。改为用 `cloneNode(true)` 复制、设好 `src` 后替换原元素：两引擎在所有时机都带参数加载，`history.length` 不变，懒加载时 WebKit 只加载一次。`site.js` 据此修改；计划 §5.6、§8 与 V-7 断言就地修订；`docs/docs-ssg.md` 的 Embedded forms 写明元素被替换、持有它的脚本要在加载后重新查找；`landing.spec.ts` 的该测试改为在新上下文中分别打开带参数和不带参数的落地页，断言嵌入收到参数且会话历史条数相同。
2. **JS 关的表单（测试问题）**。按钮在 720 px 视口之外，站点 CSS 在 `prefers-reduced-motion: no-preference` 下给 `html` 设了 `scroll-behavior: smooth`，Playwright 滚动后前两次稳定性检查失败，第三次重试的 20 ms 等待用的是页面定时器，Chromium 关闭脚本时它不触发，点击一直挂起。按仓库同类测试（`home.spec.ts`、`islands.spec.ts`、`i18n.spec.ts`）的做法，给该测试的上下文加 `reducedMotion: "reduce"`。页面本身不受影响（WebKit 首轮已通过）。
3. **Firefox 的运行方式（环境）**。`npx playwright install firefox` 因已标记安装完成而没有动作；`--force` 重装（下载 Firefox 155.0，构建 1543）后仍报 “Could not find profile folder”，不带 `-profile` 直接运行二进制也一样，沙箱外同样失败：这一构建不能在 macOS 27.0.1 上启动。改用 Playwright 1.63 的 `channel: "moz-firefox"`（WebDriver BiDi）驱动已安装的稳定版 Firefox：在 scratchpad 写一个包装配置，导入 `playwright.docs.config.ts`，只给 `docs-firefox` 项目加这个 channel，并把 testDir、outputDir 和 webServer 的 cwd 指回仓库，仓库配置不改。首次启动触发了 Firefox 自身已暂存的更新（158.0 → 158.0.1，由其特权更新助手完成；遗留 4 个 `org.mozilla.updater` 进程在等待，未处理），更新完成后 BiDi 正常启动。Playwright 1.63 的 BiDi 页面不实现 `updateEmulateMedia`，也不支持 `javaScriptEnabled: false`，所以依赖 `colorScheme`、`reducedMotion`、关闭脚本的测试不能作为 Firefox 证据；JS 关的表单另用 `firefoxUserPrefs: {"javascript.enabled": false}` 单独验证（输入改用鼠标与键盘事件，因为可操作性等待依赖页面定时器）。计划 §9.1 V-10 已就地写明这条路线。
4. **百度统计来源（A-2）**。见 V-13 百度一行：示例补上 `connect`，并写明 `hm.js` 的 `new Function` 违规。

- 仓库配置中的 `docs-firefox` 项目（Playwright 自带 Firefox）在本机不能运行，Firefox 证据来自稳定版 Firefox 经 BiDi 的替代运行。其中依赖 `colorScheme`、`reducedMotion`、关闭脚本的 5 个既有 `home.spec.ts`、`theme.spec.ts` 测试在 Firefox 下没有取得证据；它们覆盖的模式脚本、样式和主题行为本期未改（`site.js` 的透传段在没有 `data-rd-carry` 的页面第一步就返回），Chromium 与 WebKit 下全部通过。
- 用于取证的包装配置与脚本只在 scratchpad，未入库。
- Firefox 的自动更新在首次 BiDi 启动时被触发，已完成到 158.0.1；遗留 4 个等待中的 `org.mozilla.updater` 进程未处理，交用户决定。
