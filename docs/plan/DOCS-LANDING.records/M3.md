## 交付

- T-3：`UrlRole::Frame`（`iframe src`）、`UrlRole::FormTarget`（`form action`、`button`/`input formaction`）；片段模式下 iframe 不再按 `FORBIDDEN` 报错，改为 `srcdoc`/缺 `src` → `embedded-frame`、缺 `title` → `frame-title`、`src` 记为槽位；渲染面与 `frame` 照旧禁止。`RefKind::Frame`/`RefKind::Form` 两处映射。`resolve_references` 新参数 `landing`，新增 `frame_target`、`form_target`（`markdown_intro` 也走这两个函数，按非落地页处理）。`check_document_under` 放行配置列出来源的 iframe（且无 `srcdoc`）与跨源表单目标；无配置时不查表单。`final_documents` 跳过 `FormTarget` 槽位。fixture 的 `lp.md` 补上原生表单（三个带 `data-rd-carry` 的隐藏字段）、iframe 与外链。
- T-4：`site.js` 开头的 `carry`：只读 `location.search`，写隐藏字段 `value` 与 `a`/`iframe` 的 URL 参数，不读写存储、不发请求、不用 `innerHTML`。
- T-5：`landing-third-party.mjs`（两个端口均可为 0，启动后打印实际端口；另加 `POST /reset` 清空记录）、`landing.spec.ts`（`@policy` 三个安全门测试，其余为 M5 的 V-7）、`serve.sh` 的 `landing` 来源；`static-host.mjs` 改为打印实际监听端口，供 spec 用端口 0 启动。

## 偏差与决定

- 落地页站内表单目标与同页 `<a href>` 同路解析，计划 §5.5 已就地修订。
- `form-blocked` 的消息写出表单目标；同一 HTML 块内的相同 `form-origin` 错误按现有去重合并为一条。
- Chromium 报告被拦 iframe 时 `blockedURI` 只有 origin，spec 按 `effectiveDirective` 区分脚本与 frame；响应头与 meta 两份策略可能各报一次，断言按种类去重。
