## 性能与成本

[baseline](../../validation/dom-components-p2/baseline.json) 不变，[current](../../validation/dom-components-p2/current.json) 是同一 driver 的事件→接受值/DOM→下一帧（ms），不是 Playwright 操作计时，也不是独立 CPU 计时。

| 共同负载 | baseline p50 / p95 | current p50 / p95 | p95 增量 |
| --- | --- | --- | --- |
| checkbox | 13.5 / 14.7 | 15.1 / 16.5 | +1.8 |
| text | 7.5 / 10.0 | 11.3 / 13.3 | +3.3 |
| slider | 5.2 / 8.2 | 10.8 / 12.8 | +4.6 |
| select | 14.3 / 15.2 | 14.9 / 16.4 | +1.2 |

全部每组 45 请求/45 接受，idle 前后均 tasks=0、timers=0、observers=1、errors=0，无累积残留。p95 有明确回退，不宣称性能提升；本次均低于 16.7ms。这条指标包括帧相位和调度，不能把百分比差直接当作组件 CPU 增幅。

为解释回退，追加同环境 current-only Chrome timeline 诊断（不重测 baseline、不替代共同结果）：[摘要](../../validation/dom-components-p2/current-timeline.json)。事件派发 p95：checkbox 0.150ms、text 0.098ms、slider 0.204ms；Select 打开/选择合计样本 1.684ms。各类 layout/style/animation callbacks 同时记录。数据支持当前耗时主要落在帧/异步观察边界、未出现长时间 handler 或资源增长；没有旧版 CPU trace，不能声称精确分离出历史 CPU 差值。直接微任务探针会等 DOM 输出队列，未作为 CPU 证据。

新增能力单列 [current-only](../../validation/dom-components-p2/current-only.json)：

| 新负载 | p50 / p95 ms | 正式样本请求 / 接受 / commit |
| --- | --- | --- |
| check | 15.7 / 16.6 | 40 / 40 / 0 |
| range | 0.3 / 15.1 | 40 / 40 / 40 |
| text | 8.5 / 16.0 | 40 / 40 / 0 |

其 idle 与 geometryRules=5 前后相同；原始产品 WASM 10,136,187 B / gzip 1,085,432 B，结构 CSS 2521 / gzip 697 B。不是最小 SDK 包体：它链接整个 raw 验收应用的字段/组/Slider/Select/嵌套层/错误与生命周期入口。

共同消费者整体 WASM：3,343,729 → 11,223,107 B，gzip 528,004 → 1,270,054 B；CSS：70,314 → 94,986 B，gzip 9580 → 12,591 B；runtime CSS 796 / gzip 442 B 不变。当前消费者新增 field_samples、select_samples 及新能力测量入口，多个 wasm 导出使这些页面都可达；整体增量包含扩展验收应用，不能全部归因到旧四控件。新皮肤源 form-controls.css 为 24,155 B，另有 2521 B 结构样式及新 utilities。

独立两字段公开资料消费者提供另一条有界事实：[原始/主题结果](../../validation/dom-components-p2/public-role.json) 的 WASM 分别 1,535,951 / 1,954,142 B，使用同一 Node gzip 算法分别 324,849 / 451,611 B。它与 baseline 功能不同，不作性能对比；它说明完整测试应用的 10–11MB 不应称作最小表单成本，Themed 代码也未被强制等量带入 raw 路径。ADR-1 的拆包重评条件未被证实。
