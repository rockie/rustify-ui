## 交付行为与路径

- `rustify-dom/src/form.rs`：每个字段分别保存 Constraint、Rule、Check、Application 四个错误槽，展示按该顺序取同一 message/source。set_error 保持 Rule；重跑某来源不清除其他来源，changed 清除该字段旧错误和等待。reset 在保存中返回 false，其余清状态并递增 generation，使旧 check/等待失效；无保存时忽略旧 submitted。
- `rustify-dom/src/draft.rs`：Session 持有唯一 composing 标记；组合期间先于 parse 拦截 input，commit/escape/blur 不结束编辑。浮层 EditSession 读取实际标记，组合开始即保留编辑优先级，结束/cleanup 释放。
- `primitives/field.rs`：text_field Root/Input/Slot、text_area Root、number_field Root/Input、color_field Root/Input/Swatch、typed control_as 与原生 Label 共用实际编辑边界。TextKind 补 date/datetime-local/month/time/week/hidden；原生 name/form/required、ARIA、autocomplete/inputmode/pattern/length 等到实际 editor，wrapper class 与 input_class 分开。TextArea 保留 HTML/CR 转义与 SSR 前导 LF 规则。
- 普通文本只由接受值显示；仅在值不同时写 native value。composition 期间不发布、不回正，结束交付一次，过滤紧随的同值或拒绝后回正 input，不吞下一次不同编辑。Number/Color 复用 SDK Draft；可见编辑 input 不命名，hidden 镜像只反映接受值。数字边界仅宣告，步进仍从应用接受值请求。禁用/只读不发业务请求。
- `primitives/form.rs`：FormRoot 输出一个 novalidate 原生 form。私有注册表按逻辑控件登记 composing、可选 Draft commit、flush、focus 与实际 native owner；key 索引按注册变化缓存，不持业务值。按 form.elements 顺序对每个逻辑控件只结束/同步一次，然后重新读取约束；checkbox/radio/switch/toggle、组和 Slider 均接入同一注册表及逻辑 form owner。
- 未绑定或外部 form 关联的原生约束失败，在 FormState 之前结束：真实 checkValidity/invalid target/validationMessage 可观察，聚焦首个实际未绑定控件，不运行 rules/save、不调用 on_asked。绑定约束批量替换 Constraint 后进入既有 Form::submit；save 只由 handle 执行一次。Busy 时拒绝提交/reset；reset 总是阻止 native 默认恢复，再交应用决定业务值和 Form::reset。
- 原生 form 的父级冒泡监听让调用方 form handlers 先执行；监听均走 SDK listen，随实例 abort/Owner cleanup 释放。嵌套 FormRoot 输出诊断 div，保留内容，不产生第二个 form。Themes FormRoot 只加布局；其内 SubmitButton 为 native submit，外部保持 legacy 直接调用。修正原注释对 Save 回调的错误描述，实际 legacy 结果仍包含 Save。
- `form/field.rs`：既有 Field/control(binding) 保留并新增 description；FieldBinding 提供真实 id、description_id、error_id、source。原始 Field Root/Label/Description/Message 可自由组合，described_by 仅含已挂载提示和可见错误，消息带 data-source。Field 的第一个实际 control 继承 label id，组/Slider 不把私有 wrapper id 冒充编辑控件。
- `input.rs`、`textarea.rs`、`number_field.rs`、`color_field.rs`、`label.rs` 移除旧平行事件实现，包装同一 Primitives。每类有自己的 size 1/2/3、classic/surface/soft 类型和 ALL，color/radius 使用现有局部投影。TextArea 的 resize 支持 Responsive。TextField Slot 默认中性 11；独立 color，gap/px/pl/pr 支持 Responsive，pl/pr 保留物理含义，Start/End 随 direction 布局，utility 层保持覆盖权。

实现接缝采用计划既定的“逻辑 Control 注册，native 节点验证 owner”路线；没有公开通用 adapter、第二份默认值或逐项重复 flush。此前记录的接缝比较为单实施者自拟，不是独立或多模型评审。

## 必要修正

- TextArea 的完整原生/状态属性触及 Leptos 的 26 属性 tuple 上限；SSR 实际失败后分组追加属性，保留全部原生语义，原测试通过。
- typed editor 未声明的 pattern/autocomplete 等用可选属性集合跳过，保留目标原有属性/监听；主题 control_as 使用 additive skin class，默认 Root 不以整串 input class 覆盖宿主 target class。
- 浏览器发现旧主题未提供 P1 几何变量时，显式 size 缺 fallback 而退回 native 高度。共享几何补齐 reference 尺寸/字体/圆角 fallback；正式 ThemeScope 下的实际 24/32/40 px 与响应式规则通过。无皮肤入口不因这项皮肤修正创建主题。
- 原生 input 事件通常不可取消；取消用例改为实际可取消的 InputEvent 检查 default_prevented。Busy SubmitButton 保持既有 aria-disabled/可聚焦契约，键盘重复提交验证防重；不把 Playwright 的 enabled 过滤误判为产品点击丢失。
- runtime stats 没有 listener/scopes 字段；资源验收改用现有 Chromium CDP 查询真实 DOM listener，不把 undefined 当计数。
