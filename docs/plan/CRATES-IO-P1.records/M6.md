## 授权后执行顺序

发布人通过 Cargo 的交互 `cargo login --registry crates-io` 或受控环境配置临时凭证，确认账号/邮箱、publish-new、覆盖上述九包的名称范围及可覆盖限流窗口的有效期。若届时包已存在，先核对 owner 和版本；发布新版本还需 publish-update。只记录这些元数据，不在聊天、命令参数或仓库中传递 token。

V-13 全部通过后，从当前发布工具 checkout 执行：

```sh
python3.12 scripts/crates-io.py publish --release /Users/rockie/Documents/rustify-releases/crates-io-0.2.0-20261022/release-R1-complete --group docs
python3.12 scripts/crates-io.py verify --release /Users/rockie/Documents/rustify-releases/crates-io-0.2.0-20261022/release-R1-complete --public-docs
python3.12 scripts/crates-io.py publish --release /Users/rockie/Documents/rustify-releases/crates-io-0.2.0-20261022/release-R1-complete --group remaining
```

脚本逐包在 clean R（CLI 用 C）真实 dry-run、比较归档/锁摘要后上传，检查公开索引与下载 checksum；429 按 receipt 的 next_retry_at 续接。八包的公开 Docs 安装门通过后才上传第九包。九包齐全后应用并提交/推送已准备的公开文档，再 `verify --release <同目录> --public`，补齐 landing、迁移/回滚及九包 docs.rs 精确版本结果。V-15 全通过后才创建并推送 `rustify-libs-v0.2.0` → R、`rustify-docs-cli-v0.2.0` → C，最后回填记录。yank 不在此次授权范围，官方站点不部署。
