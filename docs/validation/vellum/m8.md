# Vellum 最终验收

验收日期：2026-09-16。环境：macOS 26.6.2、Apple M5 Pro，1600×1000、DPR 1；有头Google Chrome 152.0.7977.84，ANGLE Metal/Apple M5 Pro，原版WebGPU适配器`apple metal-3`；代码为未提交工作树，起始提交`a92caa0b5d57fc35c4a6c227c73096025107b5cd`。本报告区分浏览器自动化、截图目视检查与需要真人设备操作的项目。

## 验收口径

正式视觉参照为同浏览器的原版`ref/Vellum-main/?canvas`。每张截图的差异像素占比≤2%，RGB三个通道的绝对差之和>24才计为差异；三页亮暗、菜单/模态和编辑后的截图分别断言。比较前统一性能/引擎徽章并隐藏欢迎提示与toast，文档、相机、视口和DPR保持一致。原版WebGPU对照另作实测与目视记录，不把不同参照的结果混入这道门。

## 性能与限制

最终场景、光栅和指针脚本实测：5,000形状连续20次编辑均呈现，绘制次数为1，CPU p95为6.3 ms；30次平移输入至SDK呈现帧的p95为34.8 ms。跨分辨率冷缩放首次呈现14.7–19.6 ms、细化完成67.5–146.3 ms，耗用2–5帧。启动页171层、173实例、144次绘制、1个区域，SDK GPU账本为1,450,576字节；原始汇总见`test-results/vellum/m8-performance.json`，均为本机样本。

应用采用Canvas软件光栅读回，并通过SDK上传RGBA。回归诊断发现GPU/软件Canvas在装饰线端点存在4/120,000像素（0.003333%）差异；强制GPU虽消除这4个像素，却使冷缩放细化从约0.1秒升至约3秒。最终显式设置`willReadFrequently=true`，保留快速、稳定的读回行为，布局仍严格比较，像素遵守用户确认的2%门。

体积、应用监听计数、冷启动口径及框架职责见[框架说明](../../vellum.md)。GPU账本不是浏览器进程的总显存，页内呈现时间不是物理显示器延迟，禁用HTTP缓存不等于清空操作系统缓存。构建仍有既有分叉和示例的wasm编译警告；本次规定的Clippy检查通过。
