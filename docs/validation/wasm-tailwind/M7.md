包体（gzip -9）：utility-lab WASM 合计 3,168,454 字节（主应用 9,505,030 原始字节、compiler Worker 1,791,984 原始字节），JS 57,201；fusion-basic 静态 WASM 8,776,460 原始字节，较 M1 的 8,775,365 增 1,095；未开 utility 的示例不含 Worker 或编译器资源。

解读：没有数值 SLO，以上只作记录。compiler 冷启动显著快于 JS 参考，增量与参考同级。cn 的缓存命中慢于上游：Rust 路径每次做 UTF-16 转换、`Vec<u16>` 键 SipHash 查找并复制结果，而上游以字符串为键直接返回同一字符串；两代缓存的淘汰时机决定校验回调的调用次数，属于上游可观察行为，因此未另加原生字符串缓存（§5.1 正确性优先）。经 facade 的每次调用另有 JS/WASM 参数解析与回调句柄成本。M4 记录的 variant 构造 +12.39% 与批次 prepare +2–7% 是前后两版之间的相对差；当前批次 Node/WASM 27.2 ms（M4 后一版 26.4 ms，本次负载 9–12），未定位到单一原因，按无 SLO 记录，不宣称性能通过或回归修复。

## 缺口与未验证

- 本地完成全部检查；修改后的 CI 工作流只校验了 YAML 可解析，未在远端运行（代码评审 R1 的 F-03 补上了 oracle 安装步骤，同样只做了本地隔离验证）。上游 Tailwind 执行门依赖本地 `ref/`，不进入 CI。
- Worker 内存以 Node 中同一 facade 的线性内存高水位代替；浏览器 Worker 内存需要跨源隔离才能测，未测。
- 完整 Vite HMR / Next 项目未启动（M2 已以生产宿主差分覆盖其生命周期核心）；Windows/Linux 原生与其他浏览器未验证；原生 Makepad 窗口按计划排除。
- 性能测量时系统负载偏高，数值可能偏慢；无门槛，不影响功能验收。
