# Custom public AST grounding (read-only exploration)

Scope: public AST conversion/projection, caller mutation replay, WASM object graph, custom clone field/source preservation, errors and budget charges. No builds or tests were run; findings below are source observations and explicitly marked design implications. Repository code was not edited.

## Components Found

- `PublicAst = Arc<Vec<PublicValue>>`, `InputMutation::{Set, Splice}`, `AstCompiler`: `crates/rustify-style/src/compiler/public_api/compile_ast.rs:15,20,54`. The immutable decoded graph, ordered caller effects, and incrementally compiled optimized graph are separate objects.
- `PublicObject`: `crates/rustify-style/src/compiler/public_api/design_system.rs:27`. Contains an independent semantic `Arc<()>` identity and insertion-ordered `IndexMap<Text, PublicValue>` fields. Cloning the struct preserves semantic identity; `FromIterator` creates a new identity (`:51`), and `Arc::make_mut` provides a different storage view without replacing the semantic identity (`:137,328`).
- `PublicValue`: `design_system.rs:74`. Supports JSON-like values with array/object references and lossless `Text`; explicit undefined is represented by a singleton marker. `clone_fresh` recursively allocates new arrays/objects with a storage-keyed memo and preserves aliasing within one clone (`:84–106`).
- `Origins`: `compile_ast.rs:67`. Stores original declarations by typed declaration identity; authored rule/at-rule/comment candidates by textual `OriginKey`; theme/source tuple caches; raw candidates; and original apply array/index handles.
- `AuthoredOrigin` / `OriginKey`: `compile_ast.rs:252,270`. An authored occurrence keeps the full public object, declaration-identity descendants, and CSS shape. Keys cover rule selectors, at-rule name/params, and comment values; context/at-root have no key (`:275–284`).
- `Graph`: `crates/rustify-style-wasm/src/public_api/graph.rs:12`. Maps public array storage / public object semantic identity to retained real JavaScript handles (`:15–20`). It reads caller aliases, writes stable graph handles, and replays ordered caller mutations.
- Typed `AstNode`: `crates/rustify-style/src/compiler/ast.rs:21`. The enum contains CSS fields and optional typed source/destination for rule/at-rule/declaration/comment. No arbitrary public own-field payload exists, and at-root/context lack typed spans (`:22–66`).
- `CustomUtilities`: `crates/rustify-style/src/compiler/custom_utilities.rs:130`. Stores extracted typed bodies; normalizes functional definitions and later freshly clones bodies for each candidate.

## Flow

1. WASM `AstCompiler::new` validates the configuration and array input, reads the complete graph under cache budget, invokes `core::compile_ast_text`, checks retained native + input graph + newly materialized effects, then replays constructor mutations and retains created graph handles (`public_api.rs:486–527`). No caller mutations run before the budget admission at `:508–515`.
2. `graph::read` reads arrays by length/index and objects by `Object.keys` + `Reflect.get`; repeated acyclic JavaScript handles reuse `PublicValue` aliases (`graph.rs:42–85`). Object keys are explicitly `Object.keys`, not `Reflect.ownKeys` (`public_api.rs:23–24`): the currently represented arbitrary fields are enumerable own string fields. Symbol keys, non-enumerable properties, prototypes and descriptor semantics are outside this adapter representation. Cycles are not memo-published before descending; they hit the depth limit (`graph.rs:53–55`).
3. `Origins::convert` creates typed CSS AST, storing full original declaration objects by newly assigned typed identity (`compile_ast.rs:598–619`), and full authored rule/at-rule/comment objects in authored entries (`:651–656`). Rule/comment typed spans are initially absent. Declaration source is retained as opaque public tuple through `caller_source`, while all declaration destinations are absent. At-rule source is retained only for `@theme`, `@apply`, and utilities `@tailwind`; all at-rule destinations are absent (`:542–625`). `caller_source` constructs an empty typed Source and retains the full public tuple unparsed (`:128–137`), preserving extra Source fields and fractional offsets as public values.
4. Core setup extracts custom bodies and normalizes functional declarations (`compiler/mod.rs:247–249`; `custom_utilities.rs:251–269`), prepares variants/functions (`mod.rs:291–295`), then expands apply (`:296`). Custom definitions are removed from the main typed tree using internal markers and stored typed bodies. Apply graph later restores expanded definition bodies back into `CustomUtilities` (`apply.rs:554–570`).
5. Public setup binds authored occurrences against the surviving main tree (`compile_ast.rs:891`; `bind_sources :666–690`), creates theme replacement effects, converts apply replacements into effects using original array/index handles, converts utilities node to context, then removes utility definitions from their caller arrays (`:944–992`). One apply replacement uses index `Set`; zero or multiple replacement nodes use `Splice` (`:968–986`). `ArrayPositions` accounts for preceding removals/expansions. `remove_utility_inputs` descends through context wrappers only (`:230–248`), matching the top-level-with-context restriction.
6. `Origins::output` projects both raw candidate nodes (for caller utilities `.nodes`) and optimized build nodes. Declaration original matching is by identity (`:713–717`); other authored matching is by text key, shared declaration identities, or exact CSS shape, using each origin at most once per projection (`:718–742`). It chooses exact shape first, then maximum descendant identity overlap, then earliest occurrence (`:734–739`).
7. Projection constructs rule and at-rule objects with fixed fields (`:753,782`). It copies an entire original declaration when identity survives; otherwise it uses generated/staged declaration objects or creates fixed fields (`:791–796`). Comments can reuse their original object (`:798–800`). Original `src`/`dst`, inherited source, utilities fallback under `from`, and typed source/destination override are applied afterward (`:745–747,819–842`). Generated declaration objects are staged by new declaration identity (`:843–848`).
8. Custom candidate compilation calls `ast::clone_fresh` on each definition body (`custom_utilities.rs:470`). That clone remaps declaration identities, typed Source identity, and public location graphs within one clone memo (`ast.rs:308–363`). Fresh declaration identity no longer matches `Origins.declarations`; generic arbitrary own fields were never carried by typed AST. Existing source clone support does preserve aliases between source/destination tuples already attached to typed nodes.
9. WASM build stages native output/effects and preflights native + retained JS + output graph bytes (`public_api.rs:530–549`). Core commits after its checks (`compile_ast.rs:1227–1260`). Returning identical input/previous public array skips graph write entirely (`public_api.rs:552–558`). Otherwise graph write runs mutations first and emits output (`graph.rs:258–300`). Success replaces output graph and previous handle (`public_api.rs:573–575`).

## Boundaries

### Required upstream clone/projection semantics

- Static CSS utility handlers return `structuredClone(node.nodes)` (`utilities.ts:6095–6098`). Functional registration first normalizes caller declaration values and always assigns `child.value` for every matching declaration (`:5796–5801,5853–5874,5925`); candidate execution then performs `structuredClone(node)` (`:5928–5929`) and returns its body (`:6053`). Thus definition extras itself are not automatically emitted on the generated class wrapper; body extras are cloned.
- The clone includes arbitrary enumerable field subgraphs, so alias sharing must span the entire clone root. A source object shared via `src`, `dst`, and another extra field must become one new object in that clone. Separate candidate/expansion clones should get independent identity. The existing `PublicValue::clone_fresh` is a relevant primitive, but invoking it separately for fields or nodes would violate alias scope unless one memo is shared.
- Upstream optimization reuses declaration objects (`ast.ts:349`) but creates fresh rule/at-rule wrappers with object spread, preserving their arbitrary fields and their relative own-key positions while substituting `nodes` (`:391,430,443`). A projection that starts from `original.cloned()` for wrappers would retain semantic identity unless it explicitly creates a fresh public object; that could accidentally reuse caller/raw wrapper handles through the WASM graph.

### Raw candidate graph versus optimized build graph

- Raw generated class wrappers are newly constructed with `kind`, `selector`, `nodes` (`ref/tailwindcss/packages/tailwindcss/src/compile.ts:149–165`). They receive the cloned definition BODY; arbitrary fields belonging only to the `@utility` definition wrapper therefore do not belong on that class wrapper. `styleRule` likewise constructs only these three fields (`ast.ts:69–75`).
- Raw nested Rule/AtRule nodes inside that body retain their cloned arbitrary fields. When they survive optimization, their optimized wrappers have all enumerable fields from that raw body node through spread (`ast.ts:391,430,443`) and a newly transformed `nodes` array; the arbitrary child metadata references are shared between raw and optimized wrapper, not deep-cloned again. Declaration objects are shared directly (`:349`).
- Optimization removes empty Rules (`:385`), flattens `&` Rules (`:387–389`), conditionally retains empty at-rules (`:453–462`), hoists at-root children and removes the at-root wrapper (`:465–473`), and flattens/removes Context wrappers (`:476–485`). Extra fields from eliminated wrappers do not migrate to their surviving children.
- Current public code invokes the same projection method for the raw candidate node (`compile_ast.rs:1122–1127`) and the optimized `prepared.ast` (`:1159–1161`). These calls must respect the distinct wrapper identities/shapes already established by their respective typed graphs; wrapper metadata from a definition container or eliminated wrapper must not be inferred onto generated/surviving wrappers solely because CSS shape matches.

### Caller effect schedule

- Upstream registers custom utilities before theme node replacement (`index.ts:612–636`), runs CSS functions then apply (`:663–664`), changes utilities kind/context (`:668–672`), and finally removes custom definitions (`:674–685`). Stored old definitions, child arrays and child objects remain observable independently even after removal from input.
- Current `InputMutation` can represent declaration `value` assignments and body array changes without introducing a new host mechanism. A normalization effect must be an ordered `Set` even when the value text remains equal, because upstream executes an assignment, and setters are observable. Emitting only changed values is insufficient (`utilities.ts:5925`). Current public setup emits theme/apply/utilities/removal effects, but no functional normalization assignment journal (`compile_ast.rs:944–992`).
- Definition `@apply` effects can target original stored child arrays after definition removal. The source handle in `Replacement` maps each apply occurrence back to original array/index (`apply.rs:18–20`; `compile_ast.rs:578–585,961–986`), but this is not a full general-purpose arbitrary node origin carrier.

### Setter/splice/error behavior

- Graph synchronization writes ordinary output data properties using `Reflect.defineProperty` with enumerable/writable/configurable true (`public_api.rs:246–254`). Caller `Set` effects deliberately use `Reflect.set`, invoking setters and returning original thrown JS values; false returns become `TypeError("AST input field is not writable")` (`graph.rs:271–275`). These mechanisms must not be interchanged.
- `Splice` looks up the target's real `.splice`, converts it to Function and invokes it with the target as receiver (`graph.rs:283–292`), so overridden splice functions and thrown sentinels are observable. Replay is sequential and may leave a successful prefix of effects before failure; there is no JS rollback.
- Constructor throw happens after core setup but during effects before a facade exists (`public_api.rs:516–520`). On build crossing error, already admitted candidates/counters are kept, while `compiled` restores the last published AST (`public_api.rs:566–570`; `compile_ast.rs:1031–1035`). Existing tests expect next no-op build to reuse last output and a later changed build to include candidates admitted by the failed build (`run-public-ast-graph-wasm.mjs:183–197`; mutation setter trace `run-public-ast-mutations-wasm.mjs:108–118`).

### Fees / resource admission

- Graph read charges `size_of::<PublicValue>()` for every visited occurrence, including aliases, plus 192 bytes per new object/array before publication; text is charged while decoding lossless units (`graph.rs:49–55`; `public_api.rs:125–159`).
- Native public graph storage accounting distinguishes array/object storage and semantic object identity: `json_bytes_seen` deduplicates arrays/objects by storage, charges identity once, field capacity at 128 bytes per slot, and recursively charges keys and values (`design_system.rs:488–530`). Copy-on-write views must not be collapsed by semantic identity in this native charge.
- Expanded wire input budget recursively measures every alias occurrence's serialized size, using a memo for calculation only, so a DAG cannot bypass `input_bytes` by aliasing (`compile_ast.rs:309–391`).
- Source graph retained accounting currently traverses only typed source/destination public values (`ast.rs:221–267`). New arbitrary-field carriers require explicit accounting alongside these locations; retaining them without charge would create a budget gap.
- Native setup accounts input, origins, mutation target/value graphs and banner (`compile_ast.rs:994–1009`). Native build accounts raw candidate values, compiled graph/effects and generated declaration caches before commit (`:1183–1240`). WASM `Graph::retained_bytes` uses 96 + shallow JS estimate per handle (`graph.rs:128–132`); `output_bytes` deduplicates materialized graph by handle and counts output plus mutation value subgraphs (`:134–167`). Constructor/build add these to native retained metrics before replay (`public_api.rs:508–515,532–549`).

## Non-Obvious Things

- The reported static `build(['card'])` extra loss is mechanically explained: the cloned declaration has a new typed identity; its original fields only live in `Origins.declarations` under the old identity; new declaration projection uses a fixed object. Arbitrary nested rule/at-rule fields likewise are dropped by fixed wrapper construction even when an authored origin happens to match. No run was performed in this exploration.
- An authored text-key/shape match cannot establish cloned occurrence identity. For definitions removed into the custom arena, binding against the surviving main tree does not generally bind the stored body; fresh declaration identities differ; equal-shaped duplicate definitions are especially ambiguous. The `used` set also deliberately allows each origin at most once per projection, whereas one definition may have multiple independently cloned occurrences.
- Rule/comment and ordinary nested at-rule source/destination are only retrievable through original origin metadata today, not through the typed clone. Declaration `src` survives as a fresh cloned graph, but declaration `dst` is not attached during conversion. Source-location preservation alone is therefore narrower than whole custom node graph preservation.
- Objects have semantic identity distinct from COW storage. Graph write reuses cached JS by semantic identity, synchronizes existing properties only when unequal or absent, and does not delete fields absent from the public map (`graph.rs:191–236`). Newly generated/cloned node carriers need fresh semantic identity; stable reused declarations need their existing identity.
- The custom input harness captures old arrays/old children, extra fields, shared Source and key order via graph snapshots (`run-public-ast-custom-input-wasm.mjs:27–57`), compares constructor and every build phase (`:77–87`), and includes normalization, nested apply, duplicate definitions, frozen definitions and no-features (`:59–72`). Extra `src`/`dst` alias graphs, nested arbitrary metadata sharing, duplicate same-shaped nodes and setter-on-unchanged normalization merit targeted additional evidence, but no tests were added here.

## Open Questions

- The mechanism for typed occurrence metadata is a design choice to be settled by the architect/core explorer; this slice establishes that public-only OriginKey matching is insufficient. Need explicitly defined semantic identity for authored, custom-cloned, optimized-spread and apply-cloned objects before choosing carrier fields/maps.
- Full getter/Proxy observation order is not established: graph ingestion eagerly reads all enumerable fields before core setup, whereas upstream structuredClone occurs later for custom candidate invocation. Existing tests cover selected sentinels, not complete Proxy traces. This report does not claim full host-language equivalence.
- No test/build baseline was executed as instructed. Existing assertions are evidence of intended behavior, not evidence that the current checkout passes them.
