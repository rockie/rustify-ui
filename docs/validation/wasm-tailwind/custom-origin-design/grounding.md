## The question

How can custom utility compilation preserve arbitrary represented caller node fields, Source/tuple alias graphs and ordered caller mutations through native cloning/transformation and public raw/optimized projection, while retaining the existing identity, error and resource contracts? Phase A establishes those contracts; it does not select a carrier representation or candidate implementation.

## Overview and key concepts

Current input ingestion retains a full public graph, but native custom definition bodies retain only typed CSS fields and selected source tuples. Custom compilation gives their declarations new identities. Public projection later resolves full original declaration fields by the old identity; the custom clone therefore loses arbitrary fields even though its CSS value survives. The saved first RED demonstrates this value-versus-graph mismatch: `static: build ["card"]` omits the expected `extra: "old child"` (`docs/validation/wasm-tailwind/utf16-families-custom-input-first-red.log:5–26`). This is a persisted result read here, not a new test execution.

Three identity domains matter. Native declarations have `Arc<()>` IDs used for raw/rendered sharing. Public arrays use storage identity, while PublicObject has a semantic ID separate from its copy-on-write storage. WASM Graph maps those IDs to real JS objects. A deep custom clone must create an independent public graph while preserving aliases within that graph; an optimized wrapper is a fresh shallow copy whose metadata references remain shared with its raw wrapper; a surviving declaration remains the same public object across raw and optimized views. Those relationships are distinct (`ast.rs:308–363`; `public_api/design_system.rs:27–29,84–106`; `rustify-style-wasm/src/public_api/graph.rs:15–25`; pinned upstream `ast.ts:349,391,430,443`).

`SourceLocation.public` is a canonical source tuple graph, not a general native node origin: it can retain extra Source fields and JavaScript numeric offsets, but Context/AtRoot have no location slot and other arbitrary node fields are absent from AstNode. `InputMutation::{Set,Splice}` represents ordered writes to caller objects/arrays separately from optimized returned output (`public_api/source_map.rs:13–21,66–72`; `ast.rs:21–66`; `public_api/compile_ast.rs:17–31`).

## How it works now — observed mechanics

1. **Read and convert.** The facade reads the caller graph, preserving acyclic aliases with an object map and checking its resource limit. Object fields are `Object.keys` plus `Reflect.get`, so the represented arbitrary fields are enumerable own string fields. Symbols, non-enumerable descriptors and prototypes are outside the current adapter model; cycles hit the depth limit. Native conversion saves full declarations in `Origins.declarations` under newly created native declaration IDs and saves rule/at-rule/comment fields under structural OriginKeys. Only selected src data enters typed nodes, and caller dst is not attached to typed declarations (`rustify-style-wasm/src/public_api.rs:23–24,486–515`; `graph.rs:42–85`; `compile_ast.rs:541–656`).

2. **Extract and prepare custom definitions.** Native setup extracts utilities into owned Definition bodies, leaving internal markers for later apply processing. Functional definitions normalize their value/modifier expressions in native values; static definitions bypass normalization. Functions then mutate body values/selected at-rule params, and apply expands definitions in dependency order before restoring their bodies. These edits do not themselves issue JS caller effects (`custom_utilities.rs:251–269,696–706`; `functions.rs:351–373`; `apply.rs:43–98,521–570`; `mod.rs:243–296`).

3. **Replay constructor effects.** Public setup records theme replacement, apply replacements, utilities kind/context assignment and utility definition removal. It uses original array handles plus prefix lengths for single-node Set or zero/multiple-node Splice. The current effect schedule has no functional normalization assignment journal. Old definition objects, old child arrays and old child objects remain observable even after definition removal (`compile_ast.rs:944–992`; fixture `run-public-ast-custom-input-wasm.mjs:48–57`).

4. **Clone and compile candidates.** Each matching definition invokes `ast::clone_fresh`, remapping declaration IDs, Source pointers and attached public source graphs with one memo per invocation. Functional substitution changes or removes cloned declarations; `compile_custom` wraps the surviving body in a generated class rule. Apply introduces another fresh clone and then deliberately overwrites each descendant src with its candidate-specific apply tuple; dst is not changed by that source replacement (`custom_utilities.rs:468–495`; `utilities.rs:637–753`; `apply.rs:420–451`; `ast.rs:299–363`).

5. **Keep raw facts and render.** Accepted candidates are Arc-owned raw CompiledCandidate trees. Finalize retains unoptimized children. Render uses ordinary native Clone, then hoists/optimizes; it must preserve surviving declaration identity shared with raw trees. Public build materializes cached raw candidate projections for caller utilities nodes and optimized projections using the same generated declaration staging table (`utilities.rs:631–634`; `mod.rs:644–646`; `ast.rs:375–452`; `compile_ast.rs:1101–1164`).

6. **Project and publish.** A declaration with its original native ID can copy all original fields. A custom-cloned ID has no entry and falls back to generated/staged/fixed declaration fields. Rule/at-rule projection currently builds fixed field objects even when structural matching finds an authored entry. Other authored matching uses text keys, CSS shape and descendant declaration overlap, with one use per occurrence per projection. This is reconstruction, not an explicit carried identity from each transformed body node. Quota checks happen before commit/JS replay; after admission, host replay performs caller effects and returns output. On crossing failure the core restores the last published output while retaining admitted candidates/counters (`compile_ast.rs:713–848,1183–1261`; `rustify-style-wasm/src/public_api.rs:530–575`).

## What we found — evidenced constraints and current contracts

- **[Direct local rationale] One raw native candidate fact store, optimization during rendering.** The local design explicitly adopts this to avoid two candidate facts and excludes rebuilding caller input from Prepared.ast because that loses internal nodes, array operations and original object identity (`docs/validation/wasm-tailwind/ast-input-mutation-design.md:26,55–57`; `utilities.rs:631–634`).
- **[Direct local rationale] Pointer-indexed projection tables retain owners.** The design names address reuse as the reason to retain corresponding Arcs; apply occurrence wrappers also retain owners and must not substitute shared tuple content for node identity (`ast-input-mutation-design.md:26,39`; current raw table `compile_ast.rs:77,1117–1135`).
- **[Direct local constraint] Canonical caller source data includes a full public graph and JS number offsets; typed spans use UTF-16 units.** Public metadata wins in serialization/location resolution. Equal Source text does not imply the same Source object (`source_map.rs:13–21,66–72`; `compile_ast.rs:128–137,430–443,589–590`; `M4.md:257`; map identity assertion `source_map.rs:698–734`).
- **[Direct upstream mechanics] Custom clone scopes are different from optimized spread scopes.** Pinned upstream static registration uses `structuredClone(node.nodes)`; functional registration first assigns normalized declaration value and later uses `structuredClone(node)`, returning its nodes. A generated outer class wrapper is separately constructed from kind/selector/nodes. Optimization retains declarations directly and creates new Rule/AtRule wrappers by object spread with transformed children (`ref/tailwindcss/packages/tailwindcss/src/utilities.ts:5796–5801,5925–5929,6053,6095–6098`; `compile.ts:149–165`; `ast.ts:349,391,430,443`). This is source-observed behavior, not a claim about author motivation.
- **[Supported contract] Preserve clone-local metadata aliases across all fields.** The upstream whole-root structuredClone scope, public alias-aware representation and existing source clone tests converge: a Source reached through src/dst/extra fields must be one cloned object within that clone, distinct from original and separate candidate/expansion clones. Optimized wrapper shallow copies share metadata references with raw wrappers. Cloning each field with a separate memo or deeply cloning metadata again during render would break these relationships (`utilities.ts:5929,6097`; `ast.ts:391,443`; native `ast.rs:593–632,658–666`; PublicValue clone `design_system.rs:84–106`).
- **[Supported contract] Whole-node provenance exceeds source preservation.** Typed AST lacks arbitrary node own fields, declaration dst is absent after conversion, Rule/Comment and ordinary nested at-rule src/dst rely on reconstruction, and Context/AtRoot have no typed slots. Retaining only a SourceLocation tuple cannot restore all node fields or identify every transformed occurrence (`ast.rs:21–66,152–190`; `compile_ast.rs:541–656,784–842`).
- **[Direct upstream mechanics] Constructor writes are observable even if normalized text stays equal.** Upstream executes child.value assignment after matching value/modifier declarations, registers utilities before theme replacement, runs functions then apply, changes utilities kind/context and finally removes definitions. A change-only value diff omits observable assignments (`utilities.ts:5796–5801,5925`; `index.ts:612–636,663–685`).
- **[Direct local constraint plus observed host mechanics] Resource rejection and crossing failure differ.** The design requires raw/effect/output preflight before candidate publication or JS writes. JS Set uses Reflect.set, Splice invokes the real target method with the original receiver, and output synchronization uses a separate mechanism. Successful prefixes can remain when replay throws; previously admitted candidates must survive a build crossing failure while old published output is reused (`ast-input-mutation-design.md:41–43`; `graph.rs:258–300`; facade `public_api.rs:508–517,539–570`; core `compile_ast.rs:1031–1034`).
- **[Supported contract] Full graph comparison is the acceptance shape.** The custom harness records references, ordered own fields, missing versus undefined and old caller body/array handles; it compares constructor and every build against fixed Tailwind, including duplicates, dependencies, nested apply, functions, frozen definitions and functional normalization. CSS equality alone cannot verify those contracts (`run-public-ast-custom-input-wasm.mjs:27–88`; persisted first RED cited above).

## Resource and ownership boundary

Native retained accounting currently walks typed src/dst public graphs, not arbitrary node payloads. Candidate fees include CSS estimates, declaration identities and source graphs; arbitrary metadata cannot be inferred from CSS length. Public constructor/build then charge retained Origins/input/effects/output graphs, and the facade adds retained/materialized JS handles before replay. A new retained origin graph must have an explicit charging owner across extracted definitions, cloned candidates, raw projections, optimized views and mutations (`ast.rs:221–267`; `mod.rs:575–613`; `compile_ast.rs:994–1009,1183–1240`; facade `public_api.rs:508–515,532–549`).

PublicObject semantic identity and COW storage differ: WASM handle reuse keys semantic identity, but native bytes charge each storage view and the identity separately. Charging only by semantic ID can omit actual retained storage. Conversely graph alias traversal needs memoization so a shared graph is not unnecessarily copied/charged repeatedly (`design_system.rs:488–530`; `graph.rs:15–25`). Preserving metadata by injecting a dummy location is also observable: source absence controls source inheritance, and a location's public value is printed as src. An origin carrier must not manufacture src presence merely to store non-source metadata (`ast.rs:288–305`; `compile_ast.rs:831–835`; `source_map.rs:24–35`).

## Reconciliation and what we can reasonably infer

- **[Reconciled] Fresh Source graphs and graph preservation are consistent.** The history-only report initially lacked upstream clone scope and flagged a potential tension. The public exploration plus spot-checked pinned source resolves it: custom structuredClone creates fresh identity, while preservation concerns the entire cloned graph's fields and internal aliases. It does not require reusing the original caller Source identity for a custom candidate. Existing freshness tests should remain.
- **[Inferred] An explicit transformed-occurrence origin relationship is likely needed.** Old-ID declaration lookup, key/shape matching and fixed wrapper projection cannot transport arbitrary fields across fresh custom/apply clones. A design can attach payloads or carry owned handles/maps, but it must state the whole clone scope, shallow optimized wrapper scope and current field overrides. The evidence does not select one carrier type.
- **[Inferred] Node provenance and constructor effects need separate treatment.** Carrying metadata into candidates cannot make native normalization observable on original caller objects. Ordered Set/Splice effects can express that behavior using the existing host mechanism, but their capture point/schedule and throw prefixes require verification.
- **[Inferred] Extending SourceLocation alone has structural risks.** It does not cover Context/AtRoot and uses absence as a semantic signal. A location-based candidate would have to resolve those facts explicitly; it is not ruled out by its name, nor accepted merely because Source already holds PublicValue.

## Preserve / Change / Avoid / Risk contract for Phase B

| Category | Constraint |
| --- | --- |
| Preserve | One raw candidate fact cache; render-only pruning; raw/render declaration sharing; stable cache/no-op results; Arc owners for pointer indexes. |
| Preserve | Fresh complete custom/apply clone scope, clone-local aliases, independent candidate identities; fresh shallow optimized wrappers sharing cloned metadata; removed-wrapper extras do not migrate to children; definition-container extras do not appear on generated class wrappers. |
| Preserve | Text/code units, JS public numeric offsets, Source graph fields, src/dst distinction, true source absence, missing versus explicit undefined and represented own-key order. |
| Preserve | Ordered constructor effects and original object/array targets; same-value normalization assignments; native dependency ordering; apply src override; quota preflight and crossing failure semantics. |
| Change | Carry recoverable full represented node provenance through custom/apply clones and value transformations; project current CSS fields onto that provenance with correct object freshness; record missing caller body/normalization effects. Representation is undecided. |

| Avoid | Metadata deep cloning again during optimization; fresh declaration IDs during ordinary rendering; unowned pointer maps; semantic-ID-only COW accounting; commit or JS replay before all required quota checks. |
| Risk | Clone memo scope spanning nodes/src/dst/extra aliases; multiple definitions with equal shapes; repeated apply clone boundaries; shared caller arrays; constructor writes after definition removal; thrown setter/splice prefixes; retained temporary/JS/native payload fees. |
