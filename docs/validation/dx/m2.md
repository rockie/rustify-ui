## 实现记录

### 共享页 fixture（ADR-6、D4）

- `tests/browser/support.ts` 导出 `test = base.extend(...)`：worker 级 `slot` 为每个 project 持有一页；测试级 `page` 在用例前调示例句柄的 `reset()` 并等安静，用例后移除本用例加的页面监听、`unrouteAll`、复位 emulated media/鼠标/视口，用例失败或健康检查不过（句柄缺失或 `data-status` 非 ready）即丢页、下个用例重开。
- 共享 context 始终按 project 的选项开（与哪个用例先开无关）；用例的 context 级选项（设备像素比、locale、配色、减少动效、触屏、移动端）与之不同、声明 `test.use({ fresh: true })`、或 project 不在 `HANDLES` 里时，直接用 Playwright 默认的每用例 context。
- `waitForReady`：共享页不再导航；fusion-basic 只补挂缺失的计数 scope，没挂新东西就不再重复等安静（fixture 刚等过）。
- 旧的 `sharedPage()` 已删除，原 10 个 spec 的块都改用 fixture。
- Vellum 在 `tests/vellum/support.ts` 实现同一设计（含 `browserErrors` 在共享页上的逐用例计数）。

### 缺陷修复（回归层变绿所需）

- `crates/rustify-components/src/data_table/view.rs`：视口缩小时若键盘所在单元格落出虚拟窗口，原逻辑把焦点夹到窗口里剩下的格子（`p3-table`「review · resizing at the end preserves the focused cell」在本环境改前改后都失败）。改为：尺寸变化且表格持有键盘时，把该单元格滚回视野（`goto`/`goto_column`），夹取逻辑只在读者自己滚走时生效。
- `tests/browser/p3-instances.spec.ts`：`page.evaluate` 直接返回第二实例启动的 Promise 在 Chromium 141 下报「Resulting promise was garbage collected」（改前 6 败）；`bootSecond()` 把在途 Promise 挂在 `window` 上保持可达。
- Vellum `m3-raster`「editing a new history branch…」：撤销后改文字再清空选区，2D 覆盖层仍画旧选区（应用缺陷，改前改后都失败）——修复见 [m2-vellum.md](m2-vellum.md)「覆盖层选区残留修复」。
