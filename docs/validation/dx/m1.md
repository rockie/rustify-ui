### 探针结论（A-2、A-4、A-7）

**A-2（四种隔离方式，property-workbench，各 5 次，ready + 500 ms 安静为止）**：

| 方式 | 墙钟中位 | 页内中位 | 各次墙钟 (ms) |
| --- | --- | --- | --- |
| 新 context + 导航（现状） | 9,207 ms | 9,205 ms | 7785 / 8832 / 9207 / 9298 / 9644 |
| 共享 context、新页 + 导航 | 8,815 ms | 8,813 ms | 8701 / 8716 / 8815 / 8999 / 9153 |
| 同页 `dispose()` + `mount()` | 8,200 ms | 8,197 ms | 8182 / 8200 / 8200 / 8417 / 8699 |
| 同页第二实例（对照） | 2,900 ms | 2,897 ms | 800 / 1884 / 2900 / 3216 / 4699 |

- 墙钟 ≈ 页内：时间花在页面里，不在导航或 harness。
- 拆解同页重挂：`dispose()` 65 ms、`mount()` 37 ms，随后约 0.5 s 处出现一个 **6,882 ms 的主线程长任务**；CPU profile 中 8.2 s 为 `(program)`（原生、非 JS/wasm），伴随 `getShaderParameter`/`getProgramParameter`——即 SwiftShader（ANGLE→Vulkan→Subzero）为新 WebGL 上下文同步编译/链接 Makepad 着色器。换 `--use-angle=swiftshader`、`vulkan+swiftshader`、`gl`、`--in-process-gpu` 四种启动参数，重挂仍为 6.9–9.6 s（渲染器始终是 SwiftShader）。
- 对照组「第二实例」偏低且逐次上升，挂在页面末尾的容器未参与布局，不能代表真实挂载，只作参照。
- **结论**：A-2 的「页内复位亚秒级」**对重挂式复位不成立**——每创建一次区域就付约 7–9 s，重挂与整页导航相差不到 1 s。能省下这笔的只有**保留已挂载区域、在页内把应用状态改回首载值**的复位；该偏差已写入计划 ADR-6/D4（M1 回写时修订）。计划引用的「每次导航约 10.9 s、与页面无关」（`docs/reports/p2/performance.md:76`）在本环境不成立：那部分时间是页内的区域创建。
- **Vellum**（同法，带其 config 的 SwiftShader 启动参数与 1600×1000 视口）：新 context 1,550 ms、共享 context 新页 1,502 ms、同页重挂 **883 ms**、第二实例 850 ms。Vellum 的区域只用少量着色器，重挂式复位对它足够便宜。

**A-4**：`npx playwright test --project=component-catalog` 运行中进程表只有 `xtask serve --example component-catalog --release --port 4176` 一个 server；argv 过滤在 runner 进程生效，projects 定义不受影响（`--list` 守恒）。**成立**。

**A-7**：property-workbench 回归层 `workers=2` 为 122 过、654 s（10.9 min），峰值 RSS 约 2.4 GB（chrome + node 之和，每 2 s 采样），`workers=1` 为 1,236 s、2.6 GB；15 GiB 机器上无内存压力，墙钟缩短 1.9 倍。**内存部分成立**；「本地单示例 ≤ 5 min 可达」取决于 M2 的复位方式（见 A-2 结论）。
