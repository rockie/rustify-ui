## What the checks found

**A region marked hidden was still fully laid out.** The first run of the hidden check passed the "it stopped presenting" assertion and failed the one after it, because the region had never stopped: it had never started again either, having never suspended. `[hidden] { display: none }` is in the browser's own stylesheet and loses to any rule of the page's that sets `display` on the same element - here `.b0 { display: grid }`. So the canvas kept its size, the region kept its area, and a page that thought it had put a region away went on paying for it. The page now carries the one-line override, and `docs/compatibility.md` says why an embedder needs it.

**A pointer aimed below the fold lands nowhere.** Three of the B0 checks drive the GPU half by putting a real pointer on the rectangle the region reported. The page is longer than the viewport now, and a click at a coordinate outside it is not refused - it simply does nothing, and the state does not change. Every such click now scrolls the canvas into view and measures it again first, which is the same rule M4 wrote down for a canvas that moves.

**A growth budget read through an uncollected heap is a reading of the collector.** The first B4 run put the last forty rounds at 49,852 bytes each, against a budget of 65,536 - which looked like a pass with no margin. It was mostly sawtooth: sampling after `HeapProfiler.collectGarbage` puts the same measurement at 10,444 bytes a round. What a growth gate asks about is what is still held, so the collected figure is the one that answers it.

**"Not running" is true before a job starts.** The B2 peak is meant to be sampled while a sort holds its second copy of the order. Polling for `job.running === false` answered immediately, before the first slice, and the whole check ran in 1.4 s without ever measuring a running job. It now waits for a slice to have been taken, samples, and then waits for the end - the same correction M3 made to the three write-during-a-job checks.

**Twenty controls that report a rectangle are not twenty controls on screen.** The count of GPU controls is taken from the rectangles the widgets say they drew into, and each one is asserted non-empty, because a control that laid out to nothing would otherwise be counted by the list it is named in.

## Deviations from the plan, and why

- **`document.hidden` is UNTESTED.** §5.6.2 asks for both kinds of hidden. The element kind is measured above. For the document kind, neither a second tab brought to the front nor `Page.setWebLifecycleState` made `document.hidden` true in this headless browser; the check says so and skips rather than asserting against a page that stayed visible. §5.6.2 provides for exactly this ("不可用则只测前者并记未测").
- **B4's rounds mount the counter scope, not B0.** §5.7.3 asks for two regions per instance per round, which is what the counter fixture has; B0 has one. B0 is what the page shows and what the start-up and idle figures are about, and the rounds are about mounting and unmounting, so the two-region fixture is the one that matches the load's own definition in `loads.ts`.
- **`sources.lock.json` is not edited.** §10's M6 row asks for the fork change to be registered there. The lock records what was *imported*: its digests are the import's, and `cargo xtask sources verify` reports later edits as drift, which is the mechanism the file's own `fingerprint_algorithm` note describes. Changing a digest to match an edit would remove the only evidence that the edit happened. The registration is therefore prose - `docs/compatibility.md` names the file and what the change does - which is what P2 did for its own fork change (`docs/reports/p2/compatibility.md`).
- **The GPU ledger counts uploads, not the driver.** `docs/compatibility.md` lists what is in it and what is not. The B2 table page holds under two kilobytes because the strip draws no text; the scene page, which draws ten thousand labels, holds 286,072. A gate on a figure this small is worth little on its own, which is why the check also asserts the ledger is not zero.
