## 交付

- **CLI 命令**：`new <dir> [--template content]`（先 `rustc --version` 再查目录；空/不存在目录可用、非空拒绝；同级临时目录写完再改名，失败不留残留；`.` 解析为真实目录名；非 content 模板明确拒绝）、`build [--base] [--out] [--format] [--deny-warnings]`、`preview [--dir] [--base] [--port] [--host]`、`check`（与 build 共用分析与生成，只是不写）。build 文本结论：页数、总大小、文件数、警告数、耗时，随后最大 5 页；失败最后一行为错误数与首错并声明产物未变。JSON 模式 stdout 单对象，build 的 summary 另含 files/bytes/largest/out/milliseconds。
- **内容模板**：`rustify-docs.toml`（含 logo 与 Guide 组，`url` 以注释说明）、首页（home frontmatter，actions 指向两页）、两篇指南、`static/logo.svg`、README（命令、url/base、忽略规则、托管与 CSP 说明）、`.gitignore`（`/dist/`、任意层级 `.rustify-docs/`；仓内以 `gitignore` 存放）。
- **产物**：目录+`index.html` 页面、`404.html`（同壳、一个 H1、回首页、noindex、根相对含 base 的链接）、指纹化 `assets/site.*.css`/`mode.*.js`/`site.*.js`、页面或主题引用的一切文件进 `assets/files/<名>.<指纹>.<扩展名>`（含 static 中被引用的文件与 logo）、static 目录按原路径另发、`sitemap.xml`（有 `site.url` 时，恰为非草稿且 `index` 不为 false 的页面，lastmod 取 git）、`robots.txt`（有 url 时带 Sitemap 行）、`.nojekyll`、`rustify-docs-manifest.json`（schema/mode=production/base/cli_version/build_id/文件 SHA-256 与大小，不含时间与本机路径）。
- **元数据**：唯一 `<title>`（重名按父页标题、再按路由消歧）、description、canonical/og:url（有 url）、Open Graph 与 Twitter card、分享图（新增配置 `site.image`，缺省用内置 1200×630 卡片；仅有 url 时输出）、`index: false` → noindex；页脚“编辑此页”（`repo.edit_url` + `repo.path` + 文件）与“最后更新”（一次 `git log`，UTC 日期；无仓库/无 git 时省略并警告 `no-git-history`）。
- **URL 与资源**：`Site::url` 统一对路由做路径百分号编码（含 `%`/`#`/`?`）；`srcset` 改为按 HTML 标准切分（`data:` URL 内逗号不再误切）且每个候选都发布并改写为指纹地址；仓库文件链接发布时补 `rel="noopener"`（标签已有 rel 时不加）；站点名链接只在首页标当前。
- **生成输出检查**：每个生成页过 `html_check::check_document`（无内联脚本/样式、无 on* 属性、无 script URL、脚本/样式表/资源同源、无 frame/object/base），失败为 `output-check` 错误、不发布。
- **分析新增**：`missing-site-url` 警告（附需补的配置）、`image-missing`、`config-image`、`output-conflict`（static 文件与页面、站点文件或生成前缀冲突）、`--base` 与 `site.url` 不符为 `base` 错误。
- **发布事务**（`publish`）：私有区 `<out 父目录>/.rustify-docs/<名>-<指纹>/`（lock、transaction、staging、backup）；build 独占、preview 共享 OS 锁（`File::try_lock*`，不等待）；先写完整 staging，再记 `swap` 并 out→backup、staging→out，第二步失败放回 backup；下次 build 在锁内按日志与目录状态丢弃/恢复/完成未完事务；out 必须不存在、为空或含 manifest，且不能是工程、其祖先或与内容/静态目录重叠。
- **preview**：只读 production manifest，模式/损坏/缺失/base 不符/未恢复事务均拒启并说明（base 不符时给出实际 base）；默认 127.0.0.1:4189，被占用回退系统端口，`--port 0` 由系统分配，`--host` 指定监听地址；GET/HEAD，解码后拒绝 `..`/反斜杠/NUL 并做 canonical 包含检查，目录缺斜杠 301，base 内无内容返回 404 与站点 404 页；每个响应带完整严格 CSP 头与 nosniff。
- **验证入口**：`docs-verify --group artifacts|reliability`（编排 docs 两包对应集成测试）、`--group performance` 增加真实 `rustify-docs build` B 五次与产物字节；docs Playwright 新增 `docs-root`（4191）、`docs-subpath`（4192）、`docs-meta`（4193，无响应头、无 rewrite 的 Node 静态托管），`tests/docs-ssg/serve.sh` 每次先以 docs-cli profile 重建 CLI 与 fixture；CI 新增 `docs-site` 作业，三项目逐条执行。

## 偏差与决定

- 计划 §3 资源模型未写明 static 中被页面引用的文件是否指纹化。为满足 F14/AC-2“资源改变只使自身及引用者改名”与 V-6“logo 引用链”，决定：凡页面或主题引用的文件一律按内容指纹发布，static 目录同时按原路径发布（供 favicon、CNAME 等外部已知地址）；生成器保留 `assets/site.`、`assets/mode.`、`assets/share.`、`assets/files/` 前缀与站点根文件名，static 文件占用即 `output-conflict`。
- 分享图需要绝对地址，故仅在配置 `site.url` 时输出；为此新增可选配置 `site.image`（PNG/JPEG/GIF/WebP），属于 §5.3“作者配置的已发布本地资源”的落实。
- “最后更新”无 git 时按 §4.2 警告。临时目录工程因此带 `no-git-history` 警告，相关测试按规则名断言；恰 3 错 fixture 补 `site.url` 以保持恰好 3 条诊断。
- 首页布局（tagline/actions/features 呈现）与 logo 尺寸/CLS、编辑/更新时间的视觉位置属 M5 主题，本里程碑只交付数据与最小语义 markup。
