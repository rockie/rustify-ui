## 设计记录

- **一轮一代**：单一构建线程拥有全部代；watcher 只发“有相关变化”，25 ms 静默窗口合并一批保存（最长 250 ms），构建期间到达的保存进入下一轮，最后一次保存必然被构建。每轮重新读取全部输入快照（配置、content、static、被引用片段），片段按内容与引用片段字节 hash 取缓存，再完整渲染一代；失败或 panic 不提交，继续服务上一可用代。
- **依赖失效的实现方式**：D7 的“依赖失效图”以内容寻址实现，不另建显式反向图：片段缓存键含正文、引用片段字节、语言、writer/grammar 版本与解析选项；受影响页 = 新旧两代输出逐字节比较的差集（含删除）。因此图片/片段/配置/logo 的反向依赖自然落到真正变化的页面上（资源按内容改名 → 引用页字节变化），无 mtime 判断。
- **每轮独立线程**：轮次在新线程（8 MiB 栈）上执行，panic 只随该线程的 Leptos Owner 与缓存副本一起丢弃，下一轮从上次提交的片段缓存重建；`RUSTIFY_DOCS_FAULT=panic:<标记>` 让含标记页面的渲染工作线程 panic，用于验证安装 profile 的二进制（CLI 帮助不列）。panic=abort 构建在 doctor 之前即拒绝 `dev` 并给出 `--profile docs-cli` 安装命令。
- **SSE 与刷新判定**：页面脚本以 `?session=<本次 dev>&good=<所服务代>` 加载（服务时写入，不进入代的字节）；事件流连接携带 `path` 与 `good`，服务端按每个连接判断“该地址对应的输出自 good 之后是否变化（含变为/不再是 404）”，只对受影响页下发 `reload`。这等价于计划的“SSE 带受影响 route、只有当前页受影响才刷新”，但判定放在服务端。会话 id 不同（dev 重启）即刷新；断线由 EventSource 自动重连并以 hello 消息重新同步当前 revision 与错误状态。
- **revision 语义**：成功且有变化、或任何失败（即便诊断相同）都推进 revision；成功且字节与诊断都不变（如编辑器临时文件）不推进、不广播。
- **watch 范围**：FSEvents（notify 8.2.0，延迟 0、NoDefer）递归监视工程根，只认配置文件、content/static 目录与被引用片段；`build.out`、`.git`、`.rustify-docs` 一律忽略；系统丢事件（Rescan）或 watcher 错误直接触发全量一轮。
- **端口**：`--port` 指定且被占用即失败；未指定时用 `dev.port`（默认 4188），被占用回退系统端口并在 stderr 说明；只监听 127.0.0.1；stdout 首行 `dev: <地址>`。
- **git 日期**：启动时读一次；非 git 工程只在终端提示一次，不进入面板（否则新建站点永远挂着一条与写作无关的警告）。
- **依赖**：notify 8.2.0（macOS 用 fsevent-sys，链接系统自带的 CoreServices/CoreFoundation framework，无构建脚本）。根工作区的 `bitflags` 补丁是 2.10.0，而 kqueue-sys ≥1.1 要求 `^2.11`，Cargo 不回退；在 CLI 上为 BSD/iOS 目标显式锁 kqueue =1.1.1、kqueue-sys =1.0.4（bitflags 1.x），macOS 不编译它们，不动 Makepad 补丁。features 组的 `-sys` 白名单新增 fsevent-sys、inotify-sys、kqueue-sys 并写明理由。
- **诊断面板（dev brief）**：右下 ~420 px 勘误面板，计数行（错误红、警告琥珀）+ 次行页面状态（“显示上一个可用版本 / 尚无可用版本”）+ revision + 收起；按文件分组、含错误的文件在前，条目为等宽 `行:列`、规则 id、消息（反引号内容渲染为等宽代码，路径只在 `/` 后断行）与建议；收起为同角胶囊标记（手机为全宽面板），Esc/收起按钮回到标记，标记展开后焦点到收起按钮；自动展开从不移动焦点；live region 播报计数与“问题已修复”。<640 px 为底部面板（≤50vh）。仅警告时只显示收起标记。尚无可用版本时，诊断列表作为诊断壳页正文的一部分（region，无收起/标记）。文案走 `labels.rs` 的 `DevLabels`（en/zh，经脚本标签的 `data-labels` 传入）。
- **Finish review**（impeccable-finish-reviewer，code-led、无 comp，截图 [.impeccable/review/rustify-docs-dev/](../../../.impeccable/review/rustify-docs-dev/)）：首轮 fix，6 项（文件间而非条目间分隔、标题区层级、错误优先、引用路径渲染与断行、诊断壳内联列表、手机标记形状）；复审 4 项解决、2 项回归（深色下 `--secondary` 分隔线不可见、内联面板外框过重）与 1 项缺证（长路径断行截图），修复后终审见下文。采纳的上限项：手机收起按钮 2.5rem；未采纳：列表溢出提示、每文件计数。
