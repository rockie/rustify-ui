## 设计记录

- **外链检查（§5.1 `check --external-links`）**：放在 CLI（库的分析保持不联网）。收集已发布页的 Markdown/原始 HTML 链接、首页 actions 与 `nav.top/social` 中的 http(s) 地址，去掉 `#片段` 后按地址去重；8 路并发，5 s 连接/10 s 总超时，最多 5 次重定向，HEAD 得 405/501 时改 GET；≥400 为 `external-link` 错误，任何网络失败（DNS、超时、TLS、拒绝连接）为 `external-link-unreachable` 错误，在每个书写位置定位报告，不把查不了的链接算作可用。JSON summary 增 `external_addresses`。TLS 用 rustls（ring）+ 内置 webpki 根证书，不碰系统 TLS 库或证书库；不带该选项时这条代码路径不执行。`build` 不接受该选项。
- **发布事务加固（V-10）**：`publish_with` 在三个步骤（`staged` 新站写完旧产物未动、`moved-aside` 旧产物已移走、`swapped-in` 新站就位备份未删）回调；CLI `build` 在 `RUSTIFY_DOCS_FAULT=stop:<步骤>` 时停在该步直到被杀，测试以真实 SIGKILL 杀进程。旧产物移走失败时立即清掉 staging 与日志（不再留到下次构建）。`replaceable` 只认可 manifest 可解析且为 `production` 的目录，损坏或非 production 的 manifest、符号链接一律拒绝；输出路径不得在 `.git`/`.rustify-docs` 内；这些拒绝在渲染之前完成。`preview` 先识别未完成事务（输出被移走时报“构建中途停止”而非“没有 manifest”）。
- **N7/AC-4**：作者原始 HTML 以新窗口（任何非 `_self/_parent/_top` 的 target）打开站外地址而未写 `rel="noopener"`/`noreferrer` 时报 `new-window-opener` 错误，生成页最终检查同样把关；按 §7「拒绝发布、不静默清洗」不自动改写作者标记。Markdown 链接本就不开新窗，站外链接一律带 `rel="noopener"`。
- **V-3 不受影响的依据**：`Cargo.lock` 与 HEAD 逐包比较（裸依赖名按唯一版本归一化后），除 `rustify-docs-cli` 自身外所有既有包的版本、校验和与依赖完全相同，新增 47 个包均只被 CLI 引用（notify/ureq 及其 Windows/BSD 目标依赖）；SDK、components、启动 JS 本期未改，GPU 示例与 theme-export 解析图不变，故不重跑 V-3。
