## 交付

- **特性开关**：根 workspace 的 Leptos 不再带渲染模式；`rustify-ui` 默认 `csr`，另有 `ssr`、`gpu = [dep:rustify-makepad, csr]`；`rustify-components` 对 SDK `default-features = false` 并转发 `csr`/`ssr`/`gpu`/`utility`。GPU 模块、`GpuRegion`/`RegionState`/`RegionId`/`RegionApp`/`makepad_widgets`、GPU 控件、字体 GPU helper 与其资源测试、`utility::gpu`、资源失败 hook 均 gate 到 `gpu`。`Pace` 开 `gpu` 时仍 reexport Makepad 的类型，未开时为同形 SDK 枚举，scheduler 合同测试在两种构建下都跑。
- **中性 runtime**（`crates/rustify-ui/src/runtime.rs`）：`RuntimeHooks` 绑定（signal、defer、defer_after、observe_resize、instance、protocol），`PROTOCOL = 1`，`#[wasm_bindgen]` 直接导出 `rustify_runtime_protocol`、`rustify_runtime_boot` 与（仅未开 `gpu`）`rustify_dom_create_host`；`defer`/`defer_after`/`observe_resize`/`ResizeObservation`/`listener_options` 在 wasm32 下由 SDK 自己导出，路径与签名不随 `gpu` 变化。`mount` 在 runtime 未启动时以 `UiError::RuntimeNotStarted`（新诊断类 `RuntimeNotStarted`，登记类由 17 增至 18）拒绝。`DOM_LOADER_JS`、`DOM_RUNTIME_CSS` 与 `rustify_components::CSS` 在宿主目标可读。
- **DOM host 与 loader**（`crates/rustify-ui/web/`）：`dom-runtime.js` 是无 import、无模块状态的工厂（wasm-bindgen snippet），每实例独立 AbortController、MessageChannel 任务、定时器与 ResizeObserver 账本；fatal 顺序为标死 → abort（监听与 `release_on_abort`）→ 清 URL 所有者标记 → 清 timer/task/observer → 通知页面；启动被拒时 `release()` 释放同样资源但不报 fatal。`dom-loader.js` 校验 glue/wasm 参数、三个导出与协议号，创建 host 后再由 Rust boot 复核，失败抛 `BuildContractMismatch` 并释放 host；共享编译模块、`?instance=n` 的 glue 副本、call boundary、`InstanceDead`、最多 3 次重启、`release_container`/`show_fatal` 与 GPU loader 同合同。
- **GPU loader**（`web/loader.js`）：bridge hash 后校验 runtime 协议号，`rustify_makepad_boot` 后把同一 hooks（补 `protocol`、`instance`）交给 `rustify_runtime_boot`。`embedded.js` 与 region 的 Makepad 路径未改。
- **浮层随锚点尺寸重定位**：`Layer` 对元素/画布锚点经 runtime host 增加一个 `observe_resize`，锚点尺寸变化即重算位置；原先只在窗口滚动/缩放与浮层自身尺寸变化时重定位（PRD F17/AC-2 原文要求“浮层在锚点尺寸变化后重新定位”）。随浮层释放，实例失败时随 host 断开。
- **示例与 theme-export**：7 个示例 `rustify-ui` 显式 `features = ["gpu"]`（utility-lab 为 `["gpu", "utility"]`），Leptos 显式 `csr`；`tests/theme-export/{runtime,generator}` 显式 `gpu`，独立锁只多 SDK 的直接 `wasm-bindgen` 边。示例对 `rustify-makepad` 的直接依赖（`live_region_count`）保留。
- **隔离 fixture**（`tests/dom-only/`，独立 workspace 与锁）：`consumer/` 为 `dom-consumer` cdylib 加 `export-dom-assets` bin（只用标准库写 loader/基础 CSS/组件 CSS），页面 `public/{index.html,app.js}`；`gpu-opt-in/` 开 `gpu` 引用 GPU API；`gpu-negative/`（独立 workspace）不开 `gpu` 引用 GPU API。
- **仓内入口**：`mbx xtask build-dom --manifest-path … [--output …]`（普通 `mbx build` wasm32 + 同版本 wasm-bindgen 库 + `export-dom-assets`，固定 `CARGO_TARGET_DIR=target/dom-only`，产物默认 `target/dom/<包名>`）；`mbx xtask docs-verify --group features [--external [--git <url> --rev <sha>]]`；`mbx xtask serve --dir <目录>`（同一严格 CSP 服务）；`playwright.docs.config.ts` 的 `dom-only` 项目（端口 4190，`DOM_ONLY_DIR` 指向其他产物）。
- **文档与 CI**：README、CLAUDE.md、`docs/quickstart.md`（新增“A DOM application without GPU regions”配方、GPU 区域需开 `gpu`）、`docs/architecture.md`（两种 host 一份合同、DOM 构建管线）；`.github/workflows/verify.yml` host job 增加 SDK/components 三种构建的 test/clippy，新增 `dom-only` job（features 门 + 浏览器项目）。

## 偏差与决定

- **改前基线取 `91e81b8`**：计划调查时为 `b0a6bc5`；其后只有 `8e0ece1`（Rust 1.99.0 与 makepad 弃用修复）和文档提交。取开工 HEAD 使基线与候选同用 1.99.0，已就地修订计划 §9.2、V-3、M1 行。
- **三个 runtime 原语由 SDK 直接导出**：计划原写“应用按 fixture 薄封装导出”。依赖 crate 的 `#[wasm_bindgen]` 导出随 SDK 进入应用 wasm，消费者无需样板，已修订 §4.1。
- **DOM loader 上调 `Error.stackTraceLimit`（≥200，只升不降）**：消费者 release 默认无 fat LTO，DOM 事件处理器里的 panic 到 abort 用掉约 8 帧，glue 帧在 V8 默认 10 帧外，trap 无法归属实例（实测 glue 帧在第 14 帧）；已修订 §4.1。GPU loader 未改，fat LTO 的示例构建帧数够用且其回归通过。
- **既有 Vellum 回归失败的定位与修复**：基线 `91e81b8` 上 `tests/vellum/m5-shell.spec.ts` “reset returns … first-load state” 确定性失败（基线全量 1 次 + 单独复跑 2 次，均为 `data-rustify-theme-owner` 期望 `"1"` 实得 `"2"`）。来源：`fb28856`（2026-10-04，Theme Studio）引入 `claim_root` 的进程级认领计数，每次挂载取新号，Vellum 的就地 `reset()` 重新挂载即得新号；该测试最后修改于 2026-09-27。认领号与实例号同属身份标识（Vellum `reset()` 文档也列明实例号等“不能放回”），测试改为比较根是否被认领而非认领号。属测试期望过时，不是 M1 回归；结论与改法在此登记，未请求范围豁免。
- **`serve --dir`、`build-dom` 产物目录**：首轮 `build-dom` 的产物在根 `target/` 与 fixture 自己的 `target/` 之间漂移（取决于 xtask 是否继承到 `CARGO_TARGET_DIR`），导致浏览器读到旧产物；改为在所有 fixture 子构建上显式设置目标目录。
