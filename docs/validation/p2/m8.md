# P2 M8 report: acceptance and hand-over

Date: 2026-09-10. Machine: macOS (Darwin 25.6.0), Apple Silicon, rustc 1.97.0-nightly (2026-05-19), Node 26.1.0, Playwright 1.63.0 (bundled Chromium, SwiftShader WebGL), Tailwind CSS 4.1.13.

## Status

**Closed for P2, 2026-09-11.** Existing automated acceptance was followed by user-reported passes for real pinyin, text samples, and contrast and zoom. VoiceOver has a dialog pass and an explicit user waiver for the remaining checks. The four records in `manual/` preserve those conclusions and identify detailed observations and reference images that were not supplied. Known font limitations remain; no full screen-reader or glyph-coverage claim follows from this closure.

The P2 plan is **10/10 closed**, with M8 closed after M9/M10. The automated results below are historical; M9/M10 subsequently resolved the listed failures and recorded a fully passing automated suite. No complete build/browser suite was rerun for this documentation-only acceptance update.

### The failing step, and why it is not P2's

`math_aot::batch_edges` is a test of the fork's script VM, in
`makepad/platform/script`. P2 changed exactly three files under `makepad/` -
`os/web/from_wasm.rs`, `os/web/web.rs` and `os/web/web.js` - and none of them is
in that crate.

That is an argument, not evidence, so it was checked the way M2 checked the
endurance failure: the pre-P2 commit `550c2ef` was built in a `git worktree` and
the same test run there. It overflows its stack there too, from a freshly
compiled binary. **Not a P2 regression**, and it is in the known limitations
rather than reported as a pass.

## The accessibility tree had never been read by a test

The VoiceOver record covers three things, and only the first was checked: that
every control is announced with name, role, value and state; that nothing is
announced twice; and that the keyboard is never trapped. `page.accessibility`
appeared in no spec.

`p2-a11y.spec.ts` reads the scope's ARIA tree and asserts every operable control
has a name - over the whole tree, rather than the list of twenty
`p2-semantics` names one at a time. It checks the twenty nav entries are twenty
distinct names, that Tab from the top comes back round within 300 presses, and
that twenty tab stops with a modal open never reach the scope behind it.

That last one is what `p2-semantics` could not make: it checks Escape closes a
dialog and returns focus, and a *broken* trap passes that too.

**The trap holds**, and the first version of the test was wrong about why.
Modality here is scope-level by design: a modal makes the rest of its own scope
`inert` and leaves the host page alone, because the host page is not the SDK's
to disable. So the keyboard may leave a modal onto the host's own controls and
may never reach the scope behind it. The test asserts the second, which is the
contract.

It also found a nameless text input in the catalogue's own fixture - the
host-page control V1 uses, outside the scope and outside the check. It has a
name now anyway.

## What the sample record could be measured for

A reviewer looks for three things in the twenty B5 samples: direction, order,
and whether anything came out as a box or a blank. The first two need the
reference rendering. The third has a measurable half, and it is now measured:
no sample has zero width, a Latin pangram is as wide as its text, and the
sample with five combining marks on one letter is correctly *narrow* - which is
the same fact from the other side, because getting the marks to combine is what
makes it narrow.

Writing it caught a wrong assumption of my own first: the initial check compared
every sample's width against its character count, and the samples are exactly
the strings where that does not hold. Five marks on a letter is six characters
and one glyph; a family emoji is seven code points and one. Proportionality is
asserted only where proportionality is true.

## A composition in flight was being taken as a value

The pinyin record was going to catch this, so a test went looking for it first
and found it: typing 工作 into the property form left the object named
"gongzuo". Every `input` event reached the application, including the ones an
input method fires while it is still looking a character up, and abandoning the
lookup left the pinyin behind as the name.

Two more things were wrong for the same reason. Settling ran on those events
too, writing the held value back into the element and taking the input method's
text out of the field. And the defect was in **both** pairs of text components,
the SDK's and the component crate's - which is what happens when two
implementations share a contract and only one is ever exercised.

Both pairs now ignore input while composing and report once at
`compositionend`. `p2-ime.spec.ts` covers the two places §9.4 names, and puts
V9's ten thousand Chinese characters and emoji through the form as well - a
value the field has to *hold*, not just carry.

It does not replace the manual record. A real input method is still a real input
method; what this settles is the mechanics underneath it.

## Zoom and reflow, which turned out to be development

The plan's §9.3 asks three things of contrast and zoom: the ratios, that B1's
five journeys can be completed at 200% text zoom, and that the catalogue's
content reflows without loss at 400%. Only the first had been automated; the
other two were sitting in a manual record, and they did not need to be there.
200% zoom of a 1280-pixel window is a 640-pixel CSS viewport and 400% is 320,
which is how WCAG defines the test, and a browser can be told to be that wide.

`p2-zoom.spec.ts` drives the same five journeys as `m5-semantics` at 640 pixels
with the root font size doubled, and checks that the region still reports the
geometry it drew. `p2-reflow.spec.ts` puts the catalogue at 320 and checks the
document is no wider than the viewport and that nothing has gone missing.

**The reflow check failed, and by a lot: 557 pixels of content in a 320-pixel
viewport.** The catalogue was a fixed 220-pixel nav column beside a main column
with a minimum of its own, so it had never reflowed at any width - the page just
scrolled sideways, and nobody had looked. Fixed by making it one column below
640 pixels, wrapping the header's row of switches, letting the region take the
width it is given, and giving the capability table its own scroll container.
That last one is deliberate: WCAG allows content that genuinely needs two
dimensions to scroll inside itself, as long as the page does not.

Both specs pass now. What is left for a person is the part a measurement cannot
make: whether the reflowed pages are still *readable*.

## Historical endurance failure (resolved in M10)

`m8-endurance`'s memory tail assertion fails and predates P2 - established in M2 by building the pre-P2 commit in a `git worktree` and re-running the same assertion, which failed there with a larger margin (851,968 bytes against 786,432, on a threshold of about 420 KB). This run measured the same 851,968 bytes. The behavioural half of that test passes: everything sent is received, nothing refused, no errors.

It is reported as a known limitation, not as a P2 regression.

**What it turned out to be (M10, 2026-09-11).** Not a defect at all: the
assertion was measuring the region's text caches filling. B1 draws a name, a
position and a size for every one of a thousand objects, and a two-minute run at
ten actions a second is shorter than one lap of that set, so its tail was a cache
that had not finished filling. The test walks the lap first now. The other
failure, `math_aot::batch_edges`, was the fork's wasm interpreter built without
optimisation - threaded code needs its sibling calls turned into jumps, or every
executed instruction keeps a stack frame. Both are closed; see
[M10's report](m10.md).

## Status, stated plainly

Every automated check this release owns has a result. Two of them are failures
and both were shown, by building the pre-P2 commit and re-running them, to
predate P2. Four records need a person and none of them exists.

So: **7/8 milestones closed and M8's automated half delivered**. P2 is not
complete, and `cargo xtask verify --suite p2` will keep saying so until the four
records are handed in. That is the behaviour the command was written for.
