## Status

Delivered. A-5 holds and the guard did not need the single-step fallback §11 kept in reserve.

## A-5, measured before anything was written

The plan required a probe first, and the review had already shown the obvious approach wrong. Five measurements, in `tests/browser/p2-navigation.spec.ts`, and they stay in the suite because they are the evidence for the router's shape:

| Question | Answer |
| --- | --- |
| Does one `go()` cross several entries? | Yes, and the event that follows carries the state the entry it landed on was pushed with |
| Does stepping forward one at a time recover a multi-entry move? | No. From `/d`, `go(-3)` lands on `/a` and `go(+1)` returns to `/b` |
| Is the same URL twice one entry or two? | Two. Only the number tells them apart, so a URL cannot be the identity a guard reasons about |
| What happens to a back pressed during a recovery? | It is its own event, and every event carries the entry it is about - so the router judges by what it reads, never by counting moves it asked for |
| What about an entry the router did not push? | It has no number. That is a property of the entry, not a state the router can fall into |

## The one thing the design got wrong, and how it surfaced

The sequence number started as a running total. That is correct until a user goes back and then somewhere new: the push truncates whatever was ahead, and a number that keeps climbing asks `history.go` to travel twenty-one entries through a history that has one.

It passed in isolation and failed in a serial block, which is the only way it could have been found - the block was the first thing to go back twenty times and then navigate. **The number is a depth in the history that exists**, one more than the entry it was pushed from, so that the difference between two of them is the distance the browser has to move. A host test holds it, and `docs/navigation.md` says why.

## The one that would have shipped

Makepad resolves its resources against `location.pathname`. That is fine for a page that does not navigate. An embedded region lives inside an application that does, and the moment the workbench routed to `/objects/1` every font request went to `/objects/1/makepad_widgets/...` and 404'd.

Eleven P1 tests found it within a minute of the router landing, which is the argument for §9.2's rule that P1's suite runs at every P2 milestone exit. A region is told where the application is **deployed** now - from the build's own manifest, through the loader - rather than inferring it from an address bar somebody else is moving. It is F15 one layer down, and without a deep-link test it would have been invisible until production.

The host change is `makepad/platform/src/os/web/web.js` and `web/loader.js`. §1.2 scheduled host-bridge changes for M6; this one is recorded as an M4 deviation. It touches no message in the bridge, so the schema hash is unchanged.

## Two timeouts that were margins and became near misses

The full regression turned up two failures that were neither flakes nor
behavioural regressions, and both are worth recording rather than quietly
raising:

- `p2-catalog`'s host-control comparison waited five seconds for the region to
  be ready. The catalogue's region draws far more since M2 - eleven controls
  and their shaders - and behind thirty other tests the boot no longer fits.
  The wait is a precondition, not the thing under test; it now gets the same
  thirty seconds the other region checks give it.
- `m6-components`' third-party rebuild waited five seconds for the *first*
  render. Measured: **6,625 ms**. The workbench's panel has grown a twenty-field
  form since that test was written, and the default stopped being a margin. The
  twenty rebuilds after it keep the default, because that is what the test is
  about.

The second number belongs in M8's baseline work: a first render that costs six
and a half seconds under SwiftShader is a fact about the B1 shape, and the
plan's NFR-1 asks for exactly this measured on a real build.

## Not done here

- No nested routing, no route-level authorisation, no server redirect, no form action. Written into `compatibility.md` rather than left to be discovered.
- The workbench's URL carries the selection only. Which tab, which panel and what is open are M5's, and the plan's B1 shape is where they arrive.
- The guard's words are the application's. The SDK's own message catalogue is M7.
