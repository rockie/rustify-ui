## 性能与包体

同机同 Chrome/Metal，40 次颜色更新，单位 ms。两轮相同页面内探针，开始前等 GPU/字体稳定；原始采样保留在 JSON。

| 指标 | 保存缓存修复前 p50 / p95 | 最终 p50 / p95 |
| --- | --- | --- |
| input → DOM CSSOM 提交 | 11.0 / 11.8 | 11.0 / 11.7 |
| input → DOM 过渡稳定色 | 75.0 / 75.9 | 75.0 / 76.1 |
| input → GPU draw ack | 11.7 / 12.6 | 11.8 / 12.8 |

40 次更新的 editor resolve 都是 80；SDK 总 resolve 从 **240 降到 160**，余量包含两个局部主题 boundary 的派生快照，不能把这些不同作用域当重复解析。延迟主要落在帧调度与 CSS 过渡，此次减少解析次数，并未证明交互延迟显著改善。

240 次 HSL 输入在 60 帧中发布 **30** 次，最终 **revision=drawn_revision=70**，原 canvas 和 region 身份保持。两轮连续编辑观察到的 >50ms long tasks 都是 **0**；最终 5 秒 idle 无新增 frame，CPU TaskDuration 占比约 **0.648%**。100 个命名主题的 host 用例复现了原 autosave 的 **202 次**额外解析，缓存修复后为 **0**；保存库内容或解析环境改变仍重新验证，非法数据和缓存错配仍拒绝。

旧 catalog 基线主题切换 DOM p50/p95 为 **0.20/0.20ms**、GL submit 代理 **1.20/1.50ms**，见 [M1 基线](baseline/baseline.md)。旧链只切换不透明静态 Theme，不做完整编辑/持久化；其 GL submit 不是新链的 draw revision ack，两者不是同语义延迟承诺。新链已满足无 backlog、帧合并、最终到达与不重建的结构门。

[尺寸对比](M6/sizes.json)：最终 Theme Studio wasm **28,644,856 bytes**，manifest 中产物合计 **80,973,349 bytes**；相对旧 catalog 基线 wasm 增 **15,156,750 bytes**，字体增 **544,512 bytes**。最终 catalog wasm **13,906,734 bytes**，相对基线增 **418,628 bytes**。完整实际目录含 manifest；`report-size --compressed` 的 gzip wasm **3,458,899 bytes**、全目录 **38,790,758 bytes**，[原始报告](M6/size-final.log)。字体资源占主要静态体积，不套用旧示例的包体阈值。
