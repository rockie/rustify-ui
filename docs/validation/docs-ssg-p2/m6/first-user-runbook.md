## 验收合同

招募五位熟悉 Rust、此前未用过本框架的真实开发者。起始环境只装稳定 Rust 工具链和候选 CLI，wasm32 目标按工具链提示准备并记录初始状态。候选 CLI help 提供第一条 new 命令，此后受试者仅按生成工程 README 独立完成三个可见成果：

1. 新建站点并在开发预览中打开它。
2. 改写一页，开发预览显示自己保存后的内容。
3. 加入并注册一个新函数演示，在本地看到它可交互，源码显示与该函数 / 原文件同源。

五个符合画像、使用同一冻结候选且记录完整的真实样本中，至少四位在有效时长不超过十五分钟内独立完成全部成果。有效独立完成同时满足画像、候选身份、三个成果、时间与无人工技术帮助，不能只用“页面打开了”判通过。

首次依赖下载 / 冷编译耗时单独记录并剔除；操作、阅读、修正以及其后的增量编译等待均计入十五分钟。自动化、agent 连续路径与负责人 README 预检不代替真人结果。受帮助者不得记作独立完成，按计划保留为失败或安排替补；替补时仍保存原记录及关联原因。

## 负责人准备与招募

负责人核对每人是否熟悉 Rust、是否曾使用本框架、起始 Rust / CLI 与 wasm32 状态。只记录匿名编号；姓名、联系方式与凭据不写入本文件。预留五个记录位不表示已经招募。

开始前完成候选身份核对和记录方式说明，不为受试者预建站点、预注册函数或代写页面。给出任务目标与上述计时口径；实际 new 命令、修改位置、函数、注册和围栏由候选 help / 生成 README 自己提供。负责人不追加教程、代码答案或现场诊断提示。

观察中只记录操作、等待和可见成果。若给出技术提示、代码或代操作，立刻记下时间、内容与原因，将该次标为非独立；不能因为最后结果成功而清掉帮助记录。受试者自己依照 README 读、复制、修正和调试属于独立过程。

## 执行与计时

T0 记录在受试者开始首次查阅候选 CLI help 时；结束点是三个成果均实际可见的最后一项达成时刻，负责人用对应证据记录该时刻。使用同一连续计时记录保留起止与各段等待，不凭最终感觉估算分钟数。

只为实际首次依赖下载 / 冷编译等待建立剔除区间，并保留 terminal / 观察时间依据。首次 host 与 wasm 编译或下载重叠时取区间并集，不能重复扣时；若受试者同时阅读或操作，相关阅读 / 操作时间仍计入，不能整段扣掉。之后的保存、编译等待、页面更新、阅读、修正与排错都继续计时。缺工具链提示后的操作也如实记入，不把准备/排错整体伪装成冷编译剔除。

有效时长（秒）＝结束时间减 T0 的总经过秒数 − 允许剔除区间并集的秒数。十五分钟按不超过 900 秒判定；首次下载 / 冷编译原始耗时仍保留。无法核实的暂停或中断要注明，不能自行补一个通过时长。

计时到达十五分钟且成果未齐时，记录当时状态为超时未完成；若随后继续，单列后续观察，不把之后达成改写为十五分钟内通过。任何帮助都单记，不能以扣除帮助耗时恢复“独立完成”。
