## 0. 一句话

Rust 库和组件库的作者用 Markdown 写文档，在页面里嵌入真实编译的 Leptos 组件演示。只需一个 Rust CLI 就能构建出静态站点，部署到常见的静态托管（只要求目录索引和自定义 404 页，不需要重写规则，见 WORK-N3）。生成的页面不依赖脚本也能阅读，只有交互部分才加载 wasm。整个产品只使用 rustify-ui 的 Leptos/DOM 部分，不含 Makepad。

## 1. 背景与目标

### 1.1 问题陈述与现状

**谁被什么阻碍。** 为 Leptos 组件或 Rust 库写文档的作者，目前要在几条路之间取舍：

- mdBook：没有可运行的组件演示。
- Docusaurus、VitePress、Starlight：要引入 Node 生态，演示得用 JS 重写或嵌入 iframe。
- Leptos 官方 SSR 加 axum：需要自己搭服务端和 Markdown 管线。Rust/UI 的文档站就是这样做的，见 [app/Cargo.toml](../ref/ui-main/app/Cargo.toml) 与 [markdown_crate](../ref/ui-main/crates/_markdown_crate/Cargo.toml)。

这几条路的共同后果是：文档里的示例与真实代码分离，接口改了示例却不报错；站点要么首屏依赖脚本，要么需要服务端；作者维护文档时还得维护第二套工具链。

rustify-ui 自身也有同样的问题：

- 12 份指南（`docs/*.md`）只能在 GitHub 上阅读。
- 组件目录示例 component-catalog 依赖 GPU region，把页面状态放在内存里，没有可分享的地址，也不展示源码（`examples/component-catalog/src/main.rs:130-152`）。
- 24 个组件分类没有一处能“边读文档边运行”（[docs/components.md](components.md)）。

**为什么是现在。** [PRD-WASM-UI](PRD-WASM-UI.md) §2.5 把 SSG/hydration 列为“后续独立需求”。WASM-TAILWIND 交付后，仓库已具备纯 Rust 的样式编译器；Leptos 0.8 能在本机渲染 HTML，也支持局部水合（islands）。本 PRD 承接这条独立需求，范围只包括 DOM 部分。

### 1.2 目标（终局）

- **G1 上手快，只需 Rust。** 站点作者按 CLI 和生成工程的 README 完成新建站点、改写一页、加入一个可运行演示，并在本地预览中看到改写结果、交互和对应源码。开发阶段由本项目用户验收，以 WORK-F1/AC-5 与 UAT-15 的可见成果判定；不要求另行招募、首次用户资格或限时完成。原“五名熟悉 Rust 的首次用户中至少四名在十五分钟内完成”仅保留为历史产品研究提案，不作为当前开发或发布门槛；后续研究是否开展另行决定（D15）。
- **G2 读者先读到内容。** 读者打开任意页面，HTML 里已经有正文；禁用脚本也能阅读和导航。没有自定义交互组件的页面不下载 wasm。参考站点在本地实验室条件下达到 LCP 与 CLS 的“良好”阈值（WORK-N1）。这两个阈值借自 Core Web Vitals，但这不是对 Core Web Vitals 的实地评估：INP 与真实用户数据不在验收范围内。
- **G3 示例不过期。** 已发布的站点中，失效演示和站内失效链接、锚点、图片都是 0。演示不能编译、组件未注册或引用失效时，构建失败并指向源位置（WORK-F5、WORK-F15）。
- **G4 静态部署，不含 Makepad。** 产物部署在满足 WORK-N3 托管条件的静态托管上，根路径或子路径都可用，在严格 CSP 下零违规。CLI、框架和任一生成站点的依赖中都没有 Makepad；rustify-ui 默认只含 DOM 能力，GPU region 由需要它的应用自行开启（WORK-N3、WORK-N4、WORK-F17）。
- **G5 用自身文档验证。** rustify-ui 的 12 份指南和 24 个组件分类用本框架发布成文档站，每个分类至少有一个可运行的 DOM 演示，并且具备搜索、中英界面和 AI 输出（WORK-F16）。

### 2.3 关键业务场景

主场景：

1. 站点维护者用 CLI 新建一个组件库文档站，运行开发预览，看到首页、示例指南和一个演示。
2. 维护者在指南里写正文，用 GitHub alert 写提示框，从 Rust 源文件引用代码片段，再放入一个演示。
3. 内容贡献者修改 Markdown，浏览器一秒内刷新；写错的链接在页面内标出位置。
4. CI 运行 `check` 与 `build`，零错误后把静态产物上传到 `/rustify-ui/` 子路径。
5. 读者打开页面：先读到正文，用 Cmd/Ctrl+K 搜到其他页面，切换语言和主题，运行演示并复制源码。
6. 外部 AI 工具读取 `/rustify-ui/llms.txt`，按其中的链接取得某页的 HTML 后回答用户问题。

#### WORK-F9 搜索全站内容

#### WORK-F10 发布多语言站点

- **优先级**：medium　**重要度**：high

  - 界面文案：内置中文与英文；其他语言由维护者提供文案文件，缺少的条目回退英文。
